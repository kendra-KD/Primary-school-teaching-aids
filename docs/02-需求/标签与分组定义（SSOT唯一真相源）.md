## 0. SSOT 总规则

1. **运行时权威** = `server/src/labels.js`（经 `GET /api/labels` 返回，前端 dock 必须镜像它，不得另起一套）。
2. **统一口径**：描述为 **「12 条正向行为标签 + 3 条恢复组（温柔提醒）= 15 条 / 8 组」**。
   - 旧文档写的"12 条科学标签 / 7 组"＝只数了正向、漏算恢复组，属口径偏旧，须以本文为准。
3. **两个独立的"组"概念**：`TAG_GROUPS`（行为标签分类，8 组）与 `GROUPS`（学生分队，4 小队）**不是一回事**，UI 必须区分命名。

### 1.3 关键命名裁定（消除表述不一）

- **「恢复」vs「温柔提醒」**：内部分组 key 用 `恢复`（机制：状态可恢复），**面向老师展示名用「温柔提醒」**（理念：去羞辱化）。二者指同一组。文档统一称 **「恢复组（温柔提醒）」**；前端 dock 展示"温柔提醒"，服务端归类"恢复"，均为正确，无需改码。
- **负向分值**：运行时 `delta` 为 -2 / -3 / -1 且 `eco:0`（**不进光荣榜、不降班级生态值**，仅伙伴个体状态变化）。前端 dock 显示 `v:0` 是"展示用占位 0"，**不代表无影响**——避免误解"负向没扣分"。负向的真实后果是伙伴"蔫了/受伤"，靠 `care` 照料恢复。
- **动效名跨端差异**（仅记录备查，不影响逻辑）：前端用 `knowleaf / love / wilt / injured / tidy`，服务端用 `leaf / hug / droop / hurt / mess`。属前端本地表现别名。

## 2. 概念二：学生分队（GROUPS，4 小队）

### 2.1 定义

- 4 小队 = 🌱萌芽组 / 🔬探秘组 / 💡奇思组 / 🛡️守护组。
- **本质**：把全班学生按 **`index % 4`** 自动分到的**固定小组**。
- **用途**：① 伙伴卡显示"所属小队"；② 光荣榜"最繁荣小组"按小队聚合生态值排名。
- **与行为标签无关**：它不对应任何一条科学标签，是独立的"人怎么分组"维度。

### 2.2 与 TAG_GROUPS 的区别（消除混淆的核心）

| 维度 | GROUPS（4 小队） | TAG_GROUPS（8 组） |
|---|---|---|
| 是什么 | 学生固定分队 | 行为标签分类 |
| 数量 | 4 | 8 |
| 作用对象 | 学生 | 行为 |
| 出现在哪 | 伙伴卡"所属小队"、最繁荣小组榜 | 底部点评 dock |
| 命名示例 | 萌芽 / 探秘 / 奇思 / 守护 | 思维 / 实验 / … / 温柔提醒 |

### 2.3 给 UI 的硬要求（后续 B 阶段执行）

- 伙伴卡上的"🌱萌芽组"等必须带前缀，如 **「所属小队：萌芽组」**，明确这是学生分组、不是标签。
- "最繁荣小组"榜标题加注 **「（小队）」**，与点评 dock 的"组"区分。
- 全站"组"字出现时，必须能一眼区分"行为标签组(8)"与"学生小队(4)"，禁止混用引发歧义。

## 4. 给后续开发（B / C 阶段）的硬约束

1. **改标签只改一处**：新增 / 修改任何标签，**只动 `server/src/labels.js`**，前端 `TAG_GROUPS` 与本文档同步镜像，禁止三处分叉。
2. **"组"字必区分**：UI 出现"组"时，必须区分"行为标签组(8)"与"学生小队(4)"。
3. **负向铁律**：一律走"恢复组（温柔提醒）"，不得新增羞辱性文案；负向不改生态值、不进光荣榜。
4. **文档先行**：任何标签 / 分组变更，先更新本文档，再改码，最后同步台账 R02。
