## 1. 背景与问题

### 1.1 背景

小学科学课以**探究活动**为主（观察、实验、记录、合作、工程制作），课堂中大量值得即时强化的正向行为是「学科专属」的：提出一个好问题、规范操作酒精灯、坚持三天观察绿豆发芽、主动归位器材。这些行为在通用课堂管理工具里没有对应项，老师只能口头表扬，转瞬即逝。

### 1.2 问题定义

| # | 问题 | 现有方案的不足 |
|---|---|---|
| P1 | 课堂正向行为无法即时、可视化地强化 | 口头表扬无沉淀；纸质小红花统计成本高 |
| P2 | 通用积分工具与科学学科脱节 | ClassDojo / 希沃只有通用项，无法记录「规范操作实验」 |
| P3 | 行为评价易滑向羞辱与排名 | 扣分制导致对抗；后进生被公开标注 |
| P4 | 课堂时间紧，老师无学习成本预算 | 复杂系统老师用不起来，最终回归纸质 |
| P5 | 学生的课堂参与缺少课后延续 | 下课后与课堂学习断联 |

### 1.3 产品定位

> 一个**零安装、两步操作、学科专属**的课堂即时反馈工具：把科学课的行为变成一只看得见在长大的伙伴。

**不做什么**：不做教务系统、不做作业批改、不做家校沟通、不做通用积分工具。

## 2. 目标用户与场景

### 2.1 用户画像

| 画像 | 描述 | 核心诉求 |
|---|---|---|
| **主用户：小学科学老师** | 教 1–6 年级，每周多班多节；课堂以探究活动为主；技术接受度中等，不接受培训 | 上课 40 分钟内随手能用；能立刻看到学生反应；课后能回顾 |
| **次用户：小学生** | 1–6 年级；喜欢收集、养成、可视化成长；注意力有限 | 我的伙伴要好看、会动；我能自己选；做得好伙伴会长大 |
| **间接相关：家长** | 关注孩子在校表现 | （当前不覆盖，规划中仅通过学生转述） |

### 2.2 关键场景（User Story）

| 编号 | 场景 | 用户故事 |
|---|---|---|
| S1 | 课堂即时点评 | 作为科学老师，我在小组实验巡视时发现小A规范操作了酒精灯，我想**两步点完**就给他反馈，不要打断教学 |
| S2 | 大屏氛围 | 作为老师，我希望投影上的星球随点评实时变化，全班能一起看到「我们班又繁荣了一点」 |
| S3 | 合作可视化 | 作为老师，我希望小A和小B合作探究后，他们之间出现一条藤蔓，让合作被看见 |
| S4 | 负向行为不羞辱 | 作为老师，我点名提醒了小C器材未归位，我希望**只是伙伴蔫了一下**，他能通过表现养回来，而不是被扣分挂榜 |
| S5 | 学生自主认领 | 作为学生，我想自己从图鉴里挑一个喜欢的伙伴，而不是老师硬派 |
| S6 | 课后延续 | 作为学生，我下课后想给我的伙伴签到、答一道科学题，让它长大一点 |
| S7 | 老师实时掌握 | 作为老师，我在讲台大屏上希望自动更新，不用手动刷新就能看到学生的新互动 |
| S8 | 换设备/换电脑 | 作为老师，我换教室电脑后登录一下就能拿回我的班和数据 |

## 3. 功能需求（FR）

> 完整逐条状态见 [`需求清单与实现状态.md`](需求清单与实现状态.md)，此处为模块级需求定义。

### FR-1 老师账户与鉴权

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-1.1 | 老师可用邮箱+密码登录 | 正确凭据返回 JWT；错误凭据返回 401 与「邮箱或密码不正确」，**不得返回 5xx** |
| FR-1.2 | 登录状态持久化 | 30 天内免登录（JWT expiresIn=30d，token 存 localStorage） |
| FR-1.3 | 密码可见性切换 | 密码框右侧眼睛按钮可切换明文/密文，便于确认输入 |
| FR-1.4 | 生产环境关闭公开注册 | `ALLOW_REGISTER=false` 时注册接口返回明确提示；账号仅由 `create-teacher.js` 创建 |
| FR-1.5 | 越权防护 | 任何班级/学生资源操作必须校验归属，非本人返回 404（不泄露存在性） |

### FR-2 班级管理

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-2.1 | 建班 | 输入班级名 + 年级(1–6)；年级为**纯年级数字**，界面不出现「图鉴风格」等无关文案 |
| FR-2.2 | 班级码 | 建班后自动生成 6 位码；学生端凭码入班；老师可一键重置（原码立即失效） |
| FR-2.3 | 班级列表 | 卡片墙展示班级名、年级、学生数；按年级排序 |
| FR-2.4 | 改班 / 删班 | 支持改名、改年级、改主题；删除需二次确认，级联清理学生与行为数据 |

### FR-3 花名册

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-3.1 | 单个添加 | 输入姓名回车即加 |
| FR-3.2 | 批量导入 | 支持换行/逗号/顿号/空格分隔，自动去重、跳过空项，单次 ≤80 人 |
| FR-3.3 | 导入反馈准确 | 「新增成功但刷新失败」不得显示为「导入失败」；提示需区分成功/部分成功/失败 |
| FR-3.4 | 改名 / 删除 | 支持改名；删除学生级联清理其伙伴、藤蔓、活动数据 |
| FR-3.5 | 顺序维护 | 支持 `sort_order`，花名册按顺序展示 |
| FR-3.6 | 云端一致性 | 老师端与云端花名册双向一致；弱网/失败时降级本地并明确提示 |

### FR-4 课堂点评（核心链路）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-4.1 | 两步操作 | 点伙伴 → 点标签，无弹窗、无二次确认，总耗时 < 3 秒 |
| FR-4.2 | 服务端定分 | 客户端不得传分值；分值只由 `label_key` 在服务端映射 |
| FR-4.3 | 即时视觉反馈 | 伙伴当场播放对应特效（bloom/glow/leaf/hug/evolve/tidy）；点评对象跳动 |
| FR-4.4 | 撤销点评 | 课堂点错可一键撤销，成长值/活力/生态值同步回滚；只能撤销本人的点评 |
| FR-4.5 | 负向可恢复 | 负向标签只作用于伙伴状态（蔫/伤），且提供「照料」恢复入口；负向不计入生态值、不出光荣榜 |
| FR-4.6 | 标签字典服务端下发 | 前端标签文案与分值从 `/api/labels` 获取，保证与服务端一致 |

### FR-5 全班实时状态（大屏）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-5.1 | 伙伴墙 | 每个学生显示昵称、伙伴形象、成长值、状态（正常/蔫/伤/被爱护）、小组 |
| FR-5.2 | 光荣榜 | 成长之星 Top5、提问之星、生命守护者、整洁度；只收录正向数据 |
| FR-5.3 | 班级进度环 | 显示生态值与阶段（荒芜/绿意/繁荣）及距下一阶段进度 |
| FR-5.4 | 关系藤蔓网 | 可视化同学之间的合作连线，并给出「最佳搭档」 |
| FR-5.5 | 自动刷新 | 15 秒轮询；页面切到后台暂停轮询；数据变化时伙伴有跳动反馈 |
| FR-5.6 | 首屏可用时间 | 首屏渲染不被第三方统计脚本阻塞（Umami 延迟到 `window.onload` 异步加载）；接口 12 秒超时并给出可见的加载/失败提示 |

### FR-6 学生端（免登录）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-6.1 | 凭班级码入班 | 打开链接可自动带码；也可手输；无效码给出明确提示 |
| FR-6.2 | 选择自己 | 从本班名单中选名字，支持多班级同一学生 |
| FR-6.3 | 认领伙伴 | 从图鉴中自选 38 种伙伴之一，可自定义昵称与主色 |
| FR-6.4 | 图鉴不设年级限制 | 图鉴按标签（全部/萌系自然/生命观察/动漫原创）自由切换，**任何年级可选任意伙伴** |
| FR-6.5 | 我的伙伴主页 | 展示动画伙伴、生态值/等级进度、活动列表 |
| FR-6.6 | 互动闭环 | 签到（每日限一次 +1）、课间答题（答对 +2）、观察记录（+1）；提交后伙伴跳动反馈 |
| FR-6.7 | 记忆机制 | 本地记住已认领学生，再次打开直接进入「我的伙伴」 |

### FR-7 运营与观测

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-7.1 | 访问统计 | 老师端/学生端埋点，可回答「有哪些人在用、用了多久」 |
| FR-7.2 | 健康检查 | `GET /api/health` 返回服务与数据库状态 |
| FR-7.3 | 结构化日志 | 请求日志含 reqId、状态码、耗时；5xx 打印完整错误 |
| FR-7.4 | 部署可重复 | 一条命令完成构建+启动；不污染同机其它服务 |

## 4. 非功能需求（NFR）

| 编号 | 类别 | 要求 | 现状 |
|---|---|---|---|
| NFR-1 | 性能 | 老师端首屏可交互 < 3s（4G/校园网）；核心列表接口 P95 < 300ms | 首屏已优化（Umami 异步）；接口在测试数据量下 < 70ms |
| NFR-2 | 可用性 | 老师端在云端不可达时自动降级 localStorage，课堂不中断 | ✅ 已实现（`GP_CLOUD` 降级） |
| NFR-3 | 兼容性 | 老师机 Chrome/Edge 最新版；大屏 1920×1080 为主 | ✅ 验收通过 |
| NFR-4 | 安全 | 密钥不入库；所有 SQL 参数绑定；写接口需 JWT；登录恒定耗时比较防枚举 | ✅ 已实现 |
| NFR-5 | 隐私合规 | 仅采集姓名+课堂行为；不含手机号/头像/定位；提供隐私说明 | ⚠️ 隐私政策未落地（R20） |
| NFR-6 | 可维护性 | 无 ORM 裸 SQL 但全部参数化；表结构变更走幂等迁移脚本 | ✅ 已实现 |
| NFR-7 | 可移植性 | 前端单文件零依赖；换电脑双击可用 | ✅ 已实现 |
| NFR-8 | 数据安全 | 数据库日备份、可恢复 | ⚠️ 备份策略待落地（RK-03） |
| NFR-9 | 无障碍 | 主要操作可键盘完成；色彩对比达标；无纯颜色传达的信息 | 🟡 部分达标 |

## 5. 数据与埋点

### 5.1 采集的数据（最小化）

| 表 | 字段 | 是否含个人隐私 |
|---|---|---|
| `teachers` | email / password_hash(bcrypt) / display_name | 老师邮箱（必要） |
| `classes` | name / grade / theme_pack / class_code / eco_value | 否 |
| `students` | name / nickname / color / partner_kind / partner_stage / vitality | **姓名（未成年）** — 仅姓名，不含其它身份信息 |
| `events` | label_key / delta / 时间 | 行为记录 |
| `student_activities` | kind / detail / points / 时间 | 行为记录 |
| `vines` / `partner_claims` / `submissions` | 关系与认领记录 | 否 |

### 5.2 埋点

| 端点 | 用途 |
|---|---|
| Umami（自托管 `analytics.mealpick.me`） | 页面浏览、来源、设备；用于回答「有哪些人在用」 |
| 服务端请求日志 | 接口耗时、错误率、异常堆栈 |

## 6. 验收与度量

### 6.1 成功指标（Phase 3 试用期）

| 指标 | 目标 | 采集方式 |
|---|---|---|
| 老师愿意连续使用 | 一周内 ≥ 3 节课使用 | Umami + 日志 |
| 课堂操作耗时 | 单次点评 ≤ 3 秒 | 人工计时 |
| 学生认领率 | 班级认领率 ≥ 80% | `partner_claims` |
| 学生课后互动 | 人均每周 ≥ 2 次活动 | `student_activities` |
| 课堂中断事故 | 0 次因工具故障中断 | 故障复盘记录 |

### 6.2 验收方式

- **功能验收**：逐条对照 [`验收清单.md`](../06-测试与验收/验收清单.md)
- **真实场景验收**：李老师班级实课试用，两周后回收反馈（见 [`teacher-trial-validation-kit`](../90-历史设计资料/teacher-trial-validation-kit.md)）

## 7. 约束与依赖

| 项 | 说明 |
|---|---|
| 技术约束 | 前端不得引入框架/CDN 依赖（弱网 + 换机双击可用） |
| 环境约束 | 服务器 80/443 已被其它站点占用，必须与既有服务共存（端口从 3100/5434 起，不碰 Umami） |
| 内容约束 | 伙伴形象必须原创，禁止使用任何 IP 角色（规避版权风险） |
| 组织约束 | 单人开发 + 单服务器，不做微服务与高可用 |
| 时间约束 | 以「老师能用」为第一优先，样式与体验优化让位于功能闭环 |
