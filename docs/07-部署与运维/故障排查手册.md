# 故障排查手册

> 原则：**先读错误，再改代码。** 不分析原因就开始改，是最大的时间浪费。
> 通用三步：① 收集证据（日志 / Network / Console / 复现步骤）② 定位到具体文件与行 ③ 一次改好并复验。

---

## 1. 排查入口速查

```bash
# 后端日志（最重要）
docker logs --tail 80 gp-api
docker logs --tail 200 gp-api | grep '"level":50'          # 只看 5xx

# 容器状态
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'

# 数据库连通
docker exec gp-db pg_isready -U gp_app -d growth_planet

# Nginx 错误
tail -50 /var/log/nginx/error.log

# 前端构建产物是否注入成功
grep -c "__GP_API_BASE__" /opt/growth-planet-new/deploy/frontend-built/teacher-dashboard.html   # 期望 0
```

## 3. 详细排查

### 3.1 页面打不开 / 502 / 504

```bash
docker ps                                              # gp-api 是否 Up
docker logs --tail 50 gp-api                           # 是否启动失败
nginx -t                                               # Nginx 配置是否有效
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3100/api/health   # 后端本身是否通
```

| 发现 | 处理 |
|---|---|
| 容器不在 | `docker compose -f deploy/growth-planet-docker-compose.yml up -d` |
| 启动即退出 | 看日志；常见是 `JWT_SECRET` 未设置或 < 16 位（后端故意 fail fast） |
| 直连 3100 通、域名 502 | Nginx 配置问题：`nginx -t`、检查 `proxy_pass http://127.0.0.1:3100;`（**末尾不要加斜杠**） |
| 根本连不上服务器 | 云安全组 / 防火墙；`ss -lntp \| grep :443` |

### 3.2 页面一直转圈

**历史根因（INC-003）**：第三方统计脚本 TTFB 高且阻塞 `load`。

```bash
# 浏览器 DevTools → Network，看：
#   - analytics.mealpick.me/script.js 的 TTFB
#   - 是否有请求 pending 不返回
```

| 原因 | 处理 |
|---|---|
| 统计脚本阻塞首屏 | 确认其为 `window.onload` 后动态注入（不得写成 `<script defer>`） |
| 接口悬挂 | `GP.api()` 应有 12s `AbortSignal` 超时；检查构建产物是否包含超时逻辑 |
| 后端慢查询 | `docker logs gp-api \| grep 慢查询`；对 `/state` 做 `EXPLAIN ANALYZE` |
| 网络本身慢 | 换网络验证；检查服务器出网/入网 |

### 3.3 页面白屏、按钮无反应

**历史根因（INC-001）**：JS 注释中的 `</script>` 提前闭合 script 元素，导致 JS 全变文本。

```bash
# 浏览器 Console 是否有语法错误；Elements 里是否看到大量 JS 源码作为文本
grep -n '</script>' frontend/teacher-dashboard.html | head
```

| 原因 | 处理 |
|---|---|
| 内联 JS 中出现未转义的 `</script>` | 写成 `<\/script>` |
| 某处 JS 抛错中断后续初始化 | Console 定位报错行；检查 `renderXxx()` 是否访问了未定义数据 |
| 云同步层异常中断初始化 | 确认初始化链路对网络失败有 try/catch 与降级 |

### 3.4 登录按钮不显示

**历史根因（INC-002）**：构建脚本全局替换把判断语句也替换了，`GP_CLOUD` 恒为 false。

```bash
grep -o "GP_API_BASE[^;]*" deploy/frontend-built/teacher-dashboard.html
grep -c "__GP_API_BASE__" deploy/frontend-built/teacher-dashboard.html   # 期望 0
```

| 期望 | 说明 |
|---|---|
| 赋值语句为 `window.GP_API_BASE = ''` | 已注入 |
| 判断语句仍为 `if(GP_API==='__GP_API_BASE__')` | **未被误替换** ← 关键 |

处理：修正 `build-frontend.sh` 的 sed 为精确匹配（只替换赋值语句），重新构建。

### 3.5 登录报 Internal Server Error

**历史根因（INC-005）**：Fastify 钩子 `reply.send()` 缺 `return`，处理器继续执行抛错变 500。

```bash
curl -sS -i -X POST https://gp.mealpick.me/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"luyulin@mealpick.me","password":"wrong"}'

# 期望：401 {"error":"邮箱或密码不正确"}
# 若返回 500 且是纯文本 → 大概率是错误处理链路问题
```

| 检查点 | 正确写法 |
|---|---|
| `app.decorate('authenticate', ...)` | `catch` 中必须 `return reply.code(401).send(...)` |
| 前端 `GP.login()` | `pullAll()` 需 try/catch，避免同步失败误报为登录失败 |

**取 token 的正确姿势**（不要用 sed 抓 JSON，会被引号转义坑到）：

```bash
TOKEN=$(curl -sS -X POST https://gp.mealpick.me/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"luyulin@mealpick.me","password":"真实密码"}' \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).token))")
```

### 3.6 某项操作报 500

统一流程：

```bash
# 1) 复现并立刻看日志（含 err.stack 与具体文件行）
docker logs --tail 30 gp-api
```

按 `err.code` 快速定位：

| 错误码 / 信息 | 含义 | 处理 |
|---|---|---|
| `42803 column "x" must appear in the GROUP BY clause` | 聚合查询有非聚合列 | 把该列包进聚合函数（如 `MAX(x)`）或加入 `GROUP BY`。**INC-006 根因** |
| `23503 foreign key constraint violation` | 外键阻塞删除 | 外键需 `ON DELETE CASCADE`；跑 `growth-planet-migrate.sql`。**INC-004 根因** |
| `23505 duplicate key value` | 唯一约束冲突 | 如重复 `class_code` / 重复藤蔓；检查生成逻辑 |
| `42P01 relation does not exist` | 表不存在 | 未跑迁移脚本 |
| `42703 column does not exist` | 列不存在 | 未跑迁移脚本，或代码与库不一致 |
| `ECONNREFUSED` / `timeout` | 连不上数据库 | 检查 `gp-db` 容器与 `.env` 的 `DB_PASSWORD` |
| `TypeError: Cannot read properties of undefined` | 代码逻辑错误 | 看 `err.stack` 定位行号 |

**修复后必须复验**：重跑触发该错误的操作 + 对应的冒烟接口。

### 3.7 数据没同步 / 显示不对

| 现象 | 排查 |
|---|---|
| 提示「未同步，数据仍在本机」 | 网络或后端不可达；本机数据未丢，恢复后刷新即可 |
| 老师端有、云端没有 | 看 Network 里 `POST/PUT` 是否 4xx；老师端会保留本地副本 |
| 学生认领了但大屏没变化 | 大屏 15s 轮询；手动刷新；检查 `students.partner_kind` 是否写入 |
| 成长值不对 | `growth = SUM(events.delta) + SUM(student_activities.points)`；用 SQL 核对 |
| 今日得分异常 | 容器时区为 UTC，与北京时间差 8 小时，日界统计会偏差（已知问题） |

### 3.8 伙伴形象不全 / 显示成「蛋」

**历史根因**：`creature()` 中缺该 `kind` 的 SVG 实现，退化为默认「蛋」（`duckling` 曾踩坑，提交 `f0cdf16`）。

```bash
# 检查前端 LIB 与后端白名单是否一致
grep -o 'kind:"[a-z0-9_]*"' frontend/partner-demo.html | sort > /tmp/fe.txt
grep -o "'[a-z0-9_]*'" server/src/routes/students.js | sort -u > /tmp/be.txt
comm -23 /tmp/fe.txt /tmp/be.txt      # 前端有、后端没有 → 认领会报「partner_kind 非法」
```

处理：在 `teacher-dashboard.html` 与 `partner-demo.html` 的 `creature()` 中补齐 SVG，并同步 `preview-creatures.html`。规范见 [`../03-产品设计/伙伴图鉴设计（38种）.md §4`](../03-产品设计/伙伴图鉴设计（38种）.md)。

### 3.9 HTTPS / 证书问题

```bash
certbot certificates
curl -sSI https://gp.mealpick.me | head -3
```

| 现象 | 处理 |
|---|---|
| 证书过期 | `systemctl list-timers \| grep certbot`；`certbot renew --dry-run` 后 `certbot renew` |
| 浏览器提示不安全 | 确认 `ssl_certificate` 指向 `/etc/letsencrypt/live/gp.mealpick.me/` |
| HTTP 不跳转 HTTPS | 检查 certbot 生成的 80 端口 301 server 块是否存在 |

> ⚠️ 修改 Nginx 时**不要动其它 server 块**（MealPick 主站），改完先 `nginx -t`。

### 3.10 容器起不来

```bash
docker compose -f deploy/growth-planet-docker-compose.yml logs --tail 50 gp-api
docker compose -f deploy/growth-planet-docker-compose.yml logs --tail 50 gp-db
```

| 现象 | 处理 |
|---|---|
| `no configuration file provided` | compose 文件在 `deploy/` 子目录，必须加 `-f deploy/growth-planet-docker-compose.yml` |
| gp-api 启动即退出 | 看日志；多半是 `JWT_SECRET` 缺失/<16 位（后端主动 exit） |
| gp-db 一直不 healthy | 卷权限或密码不匹配；`docker exec gp-db pg_isready` |
| 端口被占用 | `ss -lntp \| grep -E '3100\|5434'`；确认没和 umami 冲突 |
| 改了 `server/` 但代码没生效 | **忘了 `--build`**；`docker compose ... up -d --build` |

## 4. 应急降级（课堂中出问题怎么救场）

| 场景 | 立刻可做的 |
|---|---|
| 后端挂了 | 老师端会自动退回本地模式，**继续上课**（数据攒在本机，恢复后同步）；或直接双击本地 `teacher-dashboard.html` |
| 大屏卡 | 刷新页面；换用本地 HTML 文件投屏 |
| 学生端打不开 | 老师在大屏上代为点评，不影响课堂主流程 |
| 数据错了 | 用「撤销点评」回滚；学生数据错误用老师端的改名/换伙伴修正 |

> **课堂优先原则**：先保证这节课能上完，再排查技术问题。
