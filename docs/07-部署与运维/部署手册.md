## 2. 首次部署（全新服务器）

```bash
# 0) 前置
#    - Docker + compose 插件已安装
#    - 域名 A 记录已指向本机
#    - 宿主 Nginx 已安装

# 1) 拉代码
cd /opt && git clone https://github.com/kendra-KD/Primary-school-teaching-aids.git growth-planet-new
cd /opt/growth-planet-new

# 2) 生成环境变量（含数据库密码与 JWT 密钥）
cp deploy/.env.example deploy/.env
#    编辑 deploy/.env：
#      DB_PASSWORD=<强随机密码>
#      JWT_SECRET=<至少 16 位强随机串>
#      ALLOW_REGISTER=false          # 生产关闭公开注册
#    ⚠️ .env 已在 .gitignore，绝不可提交

# 3) 构建前端（把 __GP_API_BASE__ 注入为同域空串）
bash deploy/build-frontend.sh
#    → 产出 deploy/frontend-built/{index,teacher-dashboard,partner-demo}.html

# 4) 启动数据库（先只起 gp-db，等健康检查通过）
docker compose -f deploy/growth-planet-docker-compose.yml up -d gp-db

# 5) 初始化表结构
docker exec -i gp-db psql -U gp_app -d growth_planet < deploy/growth-planet-init.sql

# 6) 启动后端
docker compose -f deploy/growth-planet-docker-compose.yml up -d --build

# 7) 配置宿主 Nginx（独立子域名 + /api 反代）
cp deploy/nginx/growth-planet.conf /etc/nginx/sites-available/growth-planet
ln -s /etc/nginx/sites-available/growth-planet /etc/nginx/sites-enabled/
nginx -t && nginx -s reload

# 8) 申请 HTTPS 证书
certbot --nginx -d gp.mealpick.me
#    certbot 会自动在 server 块中插入 443 监听与证书路径，并加 80→443 跳转

# 9) 创建老师账号（生产唯一建号途径）
docker exec -i gp-api node scripts/create-teacher.js luyulin@mealpick.me '你的密码' 李老师

# 10) 冒烟验证
curl -sS https://gp.mealpick.me/api/health
curl -sS -o /dev/null -w '%{http_code}\n' https://gp.mealpick.me
```

## 3. 日常部署（最常用）

### 3.1 只改了前端

```bash
cd /opt/growth-planet-new
git pull
bash deploy/build-frontend.sh
docker compose -f deploy/growth-planet-docker-compose.yml up -d    # 不需 --build
```
Nginx 直接读 `deploy/frontend-built/`，无需 reload。

### 3.2 改了后端（`server/` 或 `Dockerfile`）

```bash
cd /opt/growth-planet-new
git pull
bash deploy/build-frontend.sh
docker compose -f deploy/growth-planet-docker-compose.yml up -d --build    # ⚠️ 必须 --build
```

### 3.3 表结构有变更

```bash
cd /opt/growth-planet-new
git pull
# ① 先备份（重要！）
docker exec gp-db pg_dump -U gp_app growth_planet > /tmp/backup_$(date +%F_%H%M).sql
# ② 跑迁移（脚本幂等，可重复执行）
docker exec -i gp-db psql -U gp_app -d growth_planet < deploy/growth-planet-migrate.sql
# ③ 再重建后端
docker compose -f deploy/growth-planet-docker-compose.yml up -d --build
```

### 3.4 本地推送（Windows PowerShell / Git Bash）

```bash
cd e:\WorkBuddy\Tool\growth-planet-repo
git add -A && git commit -m "[fix] ..."
git push origin HEAD
```

> 若出现 `Recv failure: Connection was reset`——这是大文件/长连接问题，执行一次即可：
> ```bash
> git config --global http.version HTTP/1.1
> git config --global http.postBuffer 1048576000
> ```
> 认证必须用 **Personal Access Token**（不是账号密码）。

## 4. 部署后必做的验证（5 分钟）

```bash
# 1) 容器状态
docker ps --format 'table {{.Names}}\t{{.Status}}'      # gp-db / gp-api 均 Up

# 2) 日志无 5xx
docker logs --tail 50 gp-api | grep '"level":50' || echo "✅ 无 5xx"

# 3) 健康检查
curl -sS https://gp.mealpick.me/api/health

# 4) 登录（错误密码必须 401，不是 500）
curl -sS -o /dev/null -w '%{http_code}\n' -X POST https://gp.mealpick.me/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"luyulin@mealpick.me","password":"wrong"}'

# 5) 核心接口（含状态聚合，历史易错点）
TOKEN=$(curl -sS -X POST https://gp.mealpick.me/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"luyulin@mealpick.me","password":"你的真实密码"}' \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).token))")
curl -sS -o /dev/null -w 'classes=%{http_code}\n' https://gp.mealpick.me/api/classes -H "Authorization: Bearer $TOKEN"
CID=$(curl -sS https://gp.mealpick.me/api/classes -H "Authorization: Bearer $TOKEN" \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{const c=JSON.parse(s).classes[0];console.log(c?c.id:'')})")
[ -n "$CID" ] && curl -sS -o /dev/null -w 'state=%{http_code}\n' \
  "https://gp.mealpick.me/api/classes/$CID/state" -H "Authorization: Bearer $TOKEN"

# 6) 前端占位符已注入
curl -sS https://gp.mealpick.me/ | grep -c "__GP_API_BASE__"    # 期望 0
```

**然后必须在浏览器人工点通一次**：登录 → 建班/选班 → 批量导入 → 点评 → 大屏刷新。
（历史教训：接口 200 不代表页面可用，见 INC-001。）

## 5. 常用运维命令

```bash
# 查看日志（实时）
docker compose -f deploy/growth-planet-docker-compose.yml logs -f gp-api
docker logs --tail 100 gp-api

# 重启
docker compose -f deploy/growth-planet-docker-compose.yml restart gp-api

# 停止（保留数据）
docker compose -f deploy/growth-planet-docker-compose.yml down

# 停止并删除数据卷（⚠️ 数据不可恢复，仅测试环境）
docker compose -f deploy/growth-planet-docker-compose.yml down -v

# 进数据库
docker exec -it gp-db psql -U gp_app -d growth_planet

# 老师账号
docker exec -i gp-api node scripts/create-teacher.js <email> <password> <姓名>

# Nginx
nginx -t && nginx -s reload
tail -f /var/log/nginx/error.log

# 证书续期（certbot 已配置自动，需确认 timer 生效）
certbot certificates
systemctl list-timers | grep certbot
```

## 8. 环境变量清单（`deploy/.env`）

| 变量 | 必填 | 说明 |
|---|---|---|
| `DB_PASSWORD` | ✅ | gp-db 的 `gp_app` 密码 |
| `JWT_SECRET` | ✅ | ≥16 位；不足则后端启动直接失败 |
| `JWT_EXPIRES_IN` | | 默认 `30d` |
| `ALLOW_REGISTER` | | 生产建议 `false` |
| `LOG_LEVEL` | | 默认 `info` |
| `DB_HOST/DB_PORT/DB_NAME/DB_USER` | | compose 内已注入（`gp-db` / 5432 / `growth_planet` / `gp_app`） |
| `PORT` | | 默认 3100 |

## 9. 故障速查

| 症状 | 先看 | 处理 |
|---|---|---|
| 502 / 504 | `docker ps` | 容器是否 Up；`docker logs gp-api` |
| 接口 500 | `docker logs --tail 80 gp-api` 找 `err.stack` | 见 [`故障排查手册.md`](故障排查手册.md) |
| 页面白屏/按钮无反应 | 浏览器 Console | 检查是否有 JS 语法/解析错误 |
| 页面转圈 | Network 里第三方脚本耗时 | 确认统计脚本已延迟加载 |
| 登录按钮不显示 | 查看页面源码中 `GP_API_BASE` | 应为 `''` 而非 `__GP_API_BASE__` |
| 数据库连不上 | `docker exec gp-db pg_isready -U gp_app -d growth_planet` | 检查 `.env` 的 `DB_PASSWORD` |
| 证书过期 | `certbot certificates` | `certbot renew --dry-run` 后 `renew` |
