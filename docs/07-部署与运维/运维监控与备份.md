## 3. 服务监控

### 3.1 容器状态

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
# 期望：
# gp-db    Up (healthy)    127.0.0.1:5434->5432/tcp
# gp-api   Up              127.0.0.1:3100->3100/tcp
```

### 3.2 日志解读（Fastify JSON 日志）

```bash
docker logs --tail 100 gp-api

# 只看错误
docker logs --tail 200 gp-api | grep '"level":50'

# 看某次请求全链路（用 reqId 关联）
docker logs gp-api | grep 'req-42'
```

| level | 含义 | 处置 |
|---|---|---|
| 30 | info（正常请求） | 无需处理 |
| 40 | warn | 关注，如慢查询 |
| 50 | error（5xx） | **必须排查**，含 `err.stack` |

关键字段：`reqId`（请求唯一 id）、`statusCode`、`responseTime`、`err.stack`。

### 3.3 健康检查接口

```bash
curl -sS https://gp.mealpick.me/api/health
# { "ok": true, "service": "growth-planet-api", "time": "..." }
# ok=false 表示数据库不通
```

### 3.4 建议的巡检脚本（Phase 3 落地）

```bash
#!/usr/bin/env bash
# /opt/growth-planet-new/deploy/healthcheck.sh —— 建议加到 crontab，每 5 分钟
set -uo pipefail
H="https://gp.mealpick.me"
code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$H/api/health")
if [ "$code" != "200" ]; then
  echo "[$(date)] ❌ health $code" >> /var/log/gp-health.log
  # 可选：docker compose -f /opt/growth-planet-new/deploy/growth-planet-docker-compose.yml restart gp-api
fi
echo "[$(date)] ✅ $code" >> /var/log/gp-health.log
```

**当前状态**：⚠️ 尚未部署自动巡检与告警（依赖人工发现问题，属于试用期的已知不足）。

## 4. 业务数据观察（SQL）

试用期用这些查询回答「用得怎么样」（全部只读）：

```sql
-- 4.1 各班学生数与认领率
SELECT c.name,
       COUNT(s.id)                                          AS students,
       COUNT(s.partner_kind)                                AS claimed,
       ROUND(100.0 * COUNT(s.partner_kind) / NULLIF(COUNT(s.id),0), 1) AS claim_rate
  FROM classes c LEFT JOIN students s ON s.class_id = c.id
 GROUP BY c.id, c.name;

-- 4.2 近 7 天老师点评活跃度
SELECT date_trunc('day', created_at)::date AS day, COUNT(*) AS events, COUNT(DISTINCT student_id) AS students
  FROM events
 WHERE created_at >= now() - interval '7 days'
 GROUP BY 1 ORDER BY 1 DESC;

-- 4.3 学生课后互动频次（按类型）
SELECT kind, COUNT(*) AS times, SUM(points) AS points
  FROM student_activities
 WHERE created_at >= now() - interval '7 days'
 GROUP BY kind ORDER BY times DESC;

-- 4.4 标签使用分布（看哪些科学标签老师真在用）
SELECT label_key, COUNT(*) AS times, SUM(delta) AS total
  FROM events GROUP BY label_key ORDER BY times DESC;

-- 4.5 库体积
SELECT pg_size_pretty(pg_database_size('growth_planet'));
```

**试用期健康阈值建议**：认领率 ≥ 80%；老师周点评 ≥ 100 条；学生活动周 ≥ 2 次/人。

## 5. 备份策略

### 5.1 当前状态

⚠️ **只有 Docker 卷 `deploy/data/postgres`，无定时备份**（风险 RK-03，需求 R35）。
数据卷在，容器误删不丢数据；但**磁盘故障、误执行 SQL、卷损坏**都会造成不可恢复的丢失。

### 5.2 落地方案（Phase 3 必做）

```bash
# 创建目录
mkdir -p /opt/backups/gp

# /etc/cron.d/gp-backup —— 每日 03:30 备份，保留 14 天
30 3 * * * root docker exec gp-db pg_dump -U gp_app -Fc growth_planet \
  > /opt/backups/gp/growth_planet_$(date +\%F).dump \
  && find /opt/backups/gp -name '*.dump' -mtime +14 -delete
```

（可选）异地：`rclone` 同步到对象存储 OSS，保证磁盘损坏也可恢复。

### 5.3 恢复演练（每季度一次，必须真的做）

```bash
# 1) 起一个临时库验证备份可恢复（不影响生产）
docker exec -i gp-db psql -U gp_app -d postgres -c "CREATE DATABASE gp_restore_test;"
docker exec -i gp-db pg_restore -U gp_app -d gp_restore_test < /opt/backups/gp/growth_planet_2026-09-11.dump

# 2) 校验关键表行数
docker exec -i gp-db psql -U gp_app -d gp_restore_test -c \
  "SELECT (SELECT COUNT(*) FROM classes) AS classes, (SELECT COUNT(*) FROM students) AS students, (SELECT COUNT(*) FROM events) AS events;"

# 3) 清理
docker exec -i gp-db psql -U gp_app -d postgres -c "DROP DATABASE gp_restore_test;"
```

> **没做过恢复演练的备份 = 没有备份。**

## 6. 容量与性能观察点

| 指标 | 观察方式 | 阈值 / 处置 |
|---|---|---|
| 库体积 | SQL 4.5 | > 500MB 时考虑归档历史事件 |
| 慢查询 | 日志 `[db] 慢查询` | 出现即排查（`EXPLAIN ANALYZE`） |
| 容器内存 | `docker stats` | gp-api < 200MB；gp-db < 300MB（试用期规模） |
| 磁盘 | `df -h` | > 80% 时清理备份/日志 |
| `/state` 响应 | 日志 `responseTime` | P95 > 300ms 时优化聚合查询 |
| 事件表增长 | SQL 4.2 | 单班单学期约数千行，无需分表 |

## 7. 安全运维清单

| 项 | 频率 | 检查 |
|---|---|---|
| 证书有效期 | 每月 | `certbot certificates`（应 > 30 天） |

| 依赖漏洞 | 每季度 | `cd server && npm audit --omit=dev` |
| 系统更新 | 每季度 | `apt list --upgradable`（注意不要升级 Nginx 影响主站） |
