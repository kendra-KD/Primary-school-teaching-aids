**目标**：在写代码之前，把「给谁用、解决什么、长什么样」说清楚。

**关键设计落地**：
- 分值由服务端按 `label_key` 决定，前端不可传分（ADR-006）；
- 负向行为设计为「可恢复、不羞辱」，独立分组 `负向组`，`eco: 0`（ADR-007）；
- `events.delta` 存快照，保证历史评分可审计。

**上线过程中解决的问题**：
1. **网络与认证**：`git push` 报 `Recv failure: Connection was reset` → 配置 `http.version HTTP/1.1` + 加大 `http.postBuffer`，并使用 Personal Access Token 认证；
2. **compose 找不到配置**：`docker compose up` 报 `no configuration file` → 文件在 `deploy/` 子目录，必须 `-f deploy/growth-planet-docker-compose.yml`；
3. **HTTPS**：用 certbot 为 `gp.mealpick.me` 签发证书，certbot 自动改写 Nginx server 块。

**首个线上事故（INC-002）**：登录按钮不显示。
根因是 `build-frontend.sh` 用 sed 全局替换 `__GP_API_BASE__`，把判断语句 `if(GP_API==='__GP_API_BASE__')` 也替换了，导致 `GP_CLOUD` 恒为 false。修复：sed 只匹配赋值语句（提交 `fee26ac`）。

## Phase 2.1 · 稳定性修复（2026-09-11）

**目标**：修掉试用前暴露的全部阻塞性缺陷。

| 提交 | 内容 |
|---|---|
| `91feb29` | 修复鉴权钩子缺失 `return` 导致鉴权失败回退成 500（INC-005）；登录后同步失败不再误报为登录失败 |
| *本次* | 修复批量导入失败（INC-006）；建立 `docs/` 文档中心 |

### 登录 500 排查（INC-005）

用户反馈「现在登录怎么登录不了了」，截图显示 `Internal Server Error`。

排查路径（**先读日志，不盲改**）：

```bash
docker logs --tail 80 gp-api
# 发现 POST /api/auth/login → 200（登录其实是成功的）
# 但后续接口异常
curl -sS -i https://gp.mealpick.me/api/auth/login -d '...'      # 200 + token ✔
curl -sS -i https://gp.mealpick.me/api/classes -H "Authorization: Bearer $TOKEN"   # 401
```

根因：`server/src/index.js` 的 `authenticate` 钩子里：

```js
} catch (err) {
  reply.code(401).send({ error: '未登录或登录已失效' });   // ← 缺 return
}
```

Fastify 中钩子调用 `reply.send()` 后**不会自动中断路由处理器**；处理器继续执行时 `req.user` 为 `undefined`，访问 `req.user.sub` 抛 `TypeError` → 被全局错误处理器兜成 **500 纯文本**，与截图完全一致。

修复：补 `return`；同时把 `GP.login()` 的 `pullAll()` 包进 try/catch，避免「登录成功但同步失败」被误报为登录失败。

**排障过程中的反面操作（已记入规范）**：曾在 shell 里用 `sed 's/.*"token":"$[^"]*$".*/\1/'` 抓 JSON，报 `sed: invalid reference \1`——正确做法是用 `node -e` / `python -c` 解析 JSON。此条已写入 [`../04-技术设计/API接口文档.md §3.1`](../04-技术设计/API接口文档.md)。

### 批量导入失败排查（INC-006）

用户推送 `91feb29` 并部署后反馈「现在成功登录进来，但导入学生姓名失败」（附两图 + `docker logs` 输出）。

日志关键片段：

```
req-8  POST /api/classes/d9e1b6d8-.../students  → 201     ← 新增成功！
req-9  GET  /api/classes/d9e1b6d8-.../state     → 500
       DatabaseError: column "a.act_points" must appear in the GROUP BY clause
                      or be used in an aggregate function   (code 42803)
       at .../src/routes/events.js:153
```

根因：`events.js` 的「光荣榜」聚合查询中 `COALESCE(a.act_points, 0)` 的 `a.act_points` 既不在 `GROUP BY` 也未聚合。**为什么第一段查询没报错**——因为它没有 `GROUP BY`（行连接），而第二段为了算 `SUM/COUNT` 必须 `GROUP BY`，规则不同。这个功能是 Phase 2 提交 `04e4225` 引入的，当时只验证了首屏（第一段查询），**漏验了第二段聚合查询**，而它恰好在「导入学生后自动刷新」时被触发。

修复：
1. 后端 `COALESCE(MAX(a.act_points), 0)::INT`（子查询按 `student_id` 分组后每人仅一行，`MAX` 等价取值）；
2. 前端把「新增」与「刷新」的成功判定拆开——学生其实已入库，是刷新失败被误报成「导入失败」，这个错误提示本身会误导老师重复导入。

**当日同时完成**：把散落在 `design/`、`deploy/`、`README.md` 的所有文档归拢为规范化的 `docs/` 文档中心（本文档体系）。

## 阶段回顾：哪些做对了，哪些要改

### 做对了

1. **原型先行**：Phase 0 先出高保真 HTML，让老师在写后端之前就能看到东西，需求反馈非常具体（「图鉴风格」文案、dock 遮挡都是看实物才发现的）。
2. **零依赖前端**：上线至今没有出现过「环境装不上」类问题；教室电脑双击即可用这一条在真实场景里价值极高。
3. **渐进增强的云同步**：后端出问题时老师仍能上课，这是课堂工具的生命线。
4. **服务端定分**：从第一天就切断了刷分路径，后续学生端免登录才敢开放。
5. **小步提交 + 中文提交信息**：回溯历史时，只看提交标题就能重建需求脉络（本文档能写出来就依赖于此）。

### 要改

1. **验证面太窄**：连续两次事故（INC-004 外键、INC-006 聚合）都是「改动一处只验一处」。→ 已把 `/state` 与删除操作固化进冒烟清单。
2. **错误提示不准确会放大问题**：INC-006 里数据其实已写入，但提示「导入失败」会诱导老师重复导入。→ 提示必须区分失败阶段。
3. **无自动化测试是最大技术债**：两次事故都属于「跑一条 SQL 就能发现」的类型。→ Phase 4 首要补 `/state` 聚合与删除链路的集成测试。
4. **文档滞后于代码**：`design/` 里的文档在 Phase 1 后就没跟上了，导致本可以简单回答的问题（「藤蔓网怎么用」）变成了缺口。→ 本次建立 `docs/`，并把「同提交更新文档」写入规范。
5. **依赖第三方服务的可用性**：Umami 自托管实例的 TTFB 曾经拖垮主站页面。→ 第三方一律延迟加载、失败可忽略。
