# 代码与提交规范

## 1. 通用原则

1. **可读优先于聪明**：不写炫技代码；单文件里用注释分区，而不是靠复杂的模块化。
2. **小步提交**：一次提交只做一件事，能对应至少一个需求编号（`R##`）。
3. **不引入无谓依赖**：前端 0 依赖；后端生产依赖固定为 4 个（fastify / @fastify/cors / @fastify/jwt / pg / bcryptjs）。新增依赖必须说明理由。
4. **改代码同步改文档**：接口、表结构、需求状态的变更必须在同一提交内更新对应文档。

## 2. 后端（Node 22 + Fastify 5，ESM）

### 2.1 文件组织

| 文件 | 职责 | 约束 |
|---|---|---|
| `src/index.js` | 应用装配、插件注册、钩子、错误处理、优雅关闭 | 只做装配，不写业务 |
| `src/db.js` | 连接池与查询封装 | 业务代码只用 `query` / `queryOne` / `withTx`，不直接 `pool.query` |
| `src/util.js` | 错误构造与参数校验、归属校验 | 所有校验函数 `assertXxx` 失败即 `throw` |
| `src/labels.js` | 标签字典与阈值常量 | 纯数据 + 纯函数，不依赖请求上下文 |
| `src/routes/*.js` | 按领域拆分的路由 | 一个文件一个领域；导出 `default async function xxxRoutes(fastify)` |

### 2.2 编码约定

```js
// ✅ 参数化查询（永远）
const { rows } = await query(
  `SELECT * FROM students WHERE class_id = $1 ORDER BY sort_order NULLS LAST, name`,
  [classId]
);

// ❌ 绝不字符串拼接
await query(`SELECT * FROM students WHERE class_id = '${classId}'`);

// ✅ 归属校验前置
const cls = await assertOwnsClass(req.user.sub, classId);

// ✅ 事务包裹多步写操作
const result = await withTx(async (client) => {
  await client.query('INSERT INTO events ...', [...]);
  await client.query('UPDATE students ...', [...]);
  return { ... };
});

// ✅ 错误用 util 的构造器，携带 statusCode
throw badRequest('partner_kind 非法');
throw notFound('学生不存在');
```

**关键规则**：

| 规则 | 说明 |
|---|---|
| Fastify 钩子里 `reply.send()` **必须 `return`** | 否则钩子返回后处理器仍执行，抛错变 500（历史事故 R23） |
| 归属校验失败一律返回 **404**（不是 403） | 不泄露资源是否存在，防枚举 |
| 客户端传的分值一律忽略 | 分值只由服务端 `labels.js` / `kind` 决定（ADR-006） |
| 敏感比较恒定耗时 | 登录对不存在的账号也跑一次 `bcrypt.compare` |
| SQL 迁移必须幂等 | `IF NOT EXISTS` / `DROP CONSTRAINT IF EXISTS` |
| 环境变量缺失要 fail fast | `JWT_SECRET` 不足 16 位直接 `process.exit(1)` |

### 2.3 命名

| 类别 | 规范 | 示例 |
|---|---|---|
| 变量/函数 | 小驼峰 | `assertOwnsStudent`、`classStageOf` |
| 常量 | 大写下划线 | `PARTNER_KINDS`、`STAGE_THRESHOLDS` |
| 表/字段 | 小写下划线、表名复数 | `student_activities.partner_kind` |
| 路由路径 | `/api/<资源复数>` | `/api/classes/:id/state` |

## 3. 前端（原生 HTML/CSS/JS，单文件）

### 3.1 文件内部分区

两个大文件都用统一的分区注释，便于定位：

```html
<!-- ============ 1. head / 样式（设计令牌 + 组件样式） ============ -->
<!-- ============ 2. 结构（顶栏 / 星球 / 榜单 / dock / 弹窗） ============ -->
<!-- ============ 3. 数据与常量（LIB / LABELS / 图鉴） ============ -->
<!-- ============ 4. 渲染（renderTopbar / renderPlanet / renderBoard / renderRoster） ==== -->
<!-- ============ 5. 交互（点评 / 花名册 / 换班 / 弹窗） ============ -->
<!-- ============ 6. 云同步层（GP.*） ============ -->
<!-- ============ 7. 初始化 ============ -->
```

### 3.2 编码约定

| 规则 | 说明 |
|---|---|
| 所有用户输入输出经 `esc()` 转义 | 防 XSS；`esc()` 已内置 |
| 不用 CDN、不引外部字体/图标库 | 弱网可用；图标一律用 emoji 或内联 SVG |
| 网络请求统一走 `GP.api()` | 内建 `Authorization`、12s 超时、错误统一处理 |
| 第三方脚本（Umami）延迟到 `window.onload` | 不允许阻塞首屏（历史事故 R26） |
| 长任务不阻塞首屏 | 初始化先出「正在加载星球…」，再拉数据 |
| 中文文案面向小学老师 | 用「爱护实验生物」，不用「亲社会行为」 |
| 状态类名语义化 | `wilt` / `injured` / `loved` / `sel` / `active` |
| 动画只用 CSS keyframes | `breathe` / `blink` / `wig` / `hop`；避免 JS 定时器堆叠 |

### 3.3 与后端的一致性约束

> **`PARTNER_KINDS`（后端）是唯一事实来源。** 前端 `LIB` 中的 `kind` 必须 ⊆ 它。
> 新增伙伴必须四处同步（见 [`../03-产品设计/伙伴图鉴设计（38种）.md §4`](../03-产品设计/伙伴图鉴设计（38种）.md)）。

## 4. 样式规范（设计令牌）

前端使用 CSS 自定义属性统一视觉：

```css
:root{
  --bg:#0a0f1e;          /* 深空底 */
  --panel:rgba(20,28,50,.72);
  --line:rgba(127,227,192,.18);
  --mint:#7FE3C0;        /* 主色：生态绿 */
  --mint-soft:rgba(127,227,192,.25);
  --sky:#8FC7FF;         /* 次色：天空蓝 */
  --warn:#FFB38A;        /* 警示：暖橙 */
  --danger:#FF8A9B;      /* 负向：柔红（不刺眼） */
  --txt:#EAF2FF;
  --txt-dim:#98A6C4;
  --r:18px;              /* 圆角 */
}
```

- 颜色不写死在组件里，一律引用变量；
- 负向色刻意用**柔红**而非正红，避免视觉惩罚感；
- 圆角统一、阴影克制（克制发光，避免「廉价霓虹」）。

## 5. Git 提交规范

### 5.1 格式

```
[类型] 一句话说明做了什么；如需可追加第二件事

（可选正文）
- 为什么这样改（根因/背景）
- 影响范围 / 需要注意的点
```

### 5.2 类型

`[feat]` 新功能 ｜ `[fix]` 缺陷修复 ｜ `[ui]` 界面体验 ｜ `[docs]` 文档 ｜ `[refactor]` 重构 ｜ `[chore]` 杂务

### 5.3 正反例

| ❌ 反例 | ✅ 正例 |
|---|---|
| `fix bug` | `[fix] 鉴权钩子缺失 return 导致鉴权失败回退成 500` |
| `update` | `[ui] 建班年级文案简化、密码眼睛、底部 dock 收起不挡右侧` |
| `改了一堆东西` | 拆成 3 个提交，每个对应一个 `R##` |
| `修复登录问题` | `[fix] 登录 500：authenticate 钩子 reply.send 未 return，处理器继续执行取 req.user 抛错` |

### 5.4 提交前自检（与 `研发流程规范` 一致，摘要）

```
[ ] 单次提交只做一件事，能对应 R##
[ ] 提交信息说明了「做了什么」+「为什么」
[ ] 无密钥、无 .env、无 deploy/frontend-built/、无 deploy/data/
[ ] 代码能跑；关键路径点通过
[ ] 涉及的文档已同提交更新
```

### 5.5 禁止提交的内容（`.gitignore` 已覆盖）

```
.env  /  **/.env
deploy/data/            # 真实班级数据
deploy/frontend-built/  # 构建产物
deploy/certs/  deploy/letsencrypt/  deploy/certbot/
node_modules/
```

> 一旦误提交密钥：**立刻轮换密钥**（改 `JWT_SECRET` / 数据库密码），再清理历史；不要只删文件。

## 6. 代码评审（当前单人不适用，列出扩展标准）

当引入第二位开发者时：

| 检查项 | 关注点 |
|---|---|
| 正确性 | 边界条件、事务、并发写 |
| 安全 | 参数绑定、归属校验、分值是否服务端定 |
| 一致性 | `PARTNER_KINDS` 四处同步、文档同步 |
| 可读性 | 命名、分区注释、是否存在重复逻辑 |
| 影响面 | 是否影响既有接口契约（字段增删） |
| 回滚成本 | 是否可单提交回滚 |
