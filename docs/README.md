## 一、30 秒了解这个项目

| 项 | 内容 |
|---|---|
| 一句话 | 每个孩子认领一个「生命伙伴」，全班伙伴组成一颗「生态星球」，老师课堂即时点评驱动伙伴成长 |
| 用户 | 小学科学老师（试点：四川·李钰琳老师）、小学 1–6 年级学生 |
| 差异化 | 12 条**科学学科专属**行为标签（提好问题 / 观察记录 / 爱护实验生物 / 整理器材 / 工程制作 / 长期观察），通用积分工具（ClassDojo、希沃）记不下来 |
| 线上地址 | 老师端 <https://gp.mealpick.me> ｜ 学生端 <https://gp.mealpick.me/partner-demo.html> |
| 技术栈 | 前端：原生 HTML/CSS/JS 单文件（零构建、零 CDN）｜ 后端：Node 22 + Fastify 5 + PostgreSQL 14 ｜ 部署：Docker Compose + 宿主 Nginx + certbot |
| 当前阶段 | Phase 2 —— 已完成「老师端可用 + 学生端可认领可互动」闭环，进入**真实老师试用验证**阶段 |

## 四、文档维护约定（摘要）

1. **单一事实来源**：接口以 `04-技术设计/API接口文档.md` 为准，表结构以 `04-技术设计/数据库设计.md` 为准；改代码必须同步改文档，同一提交内完成。
2. **需求必留痕**：任何新需求先登记到 `02-需求/需求清单与实现状态.md` 拿到编号（R##），实现后在追溯矩阵里补上提交号。
3. **变更必记日志**：`08-项目历程/CHANGELOG.md` 按「新增 / 修复 / 变更 / 文档」四类走，与 git 提交一一对应。
4. **故障必复盘**：线上 5xx / 数据异常，48 小时内补一条到 `06-测试与验收/故障复盘记录.md`（现象 → 根因 → 修复 → 预防）。
5. 命名与目录规范详见 `05-研发流程与规范/文档整理与命名规范.md`。

## 五、快速上手命令

```bash
# 本地预览（零依赖，双击即可）
frontend/teacher-dashboard.html      # 老师大屏（未登录时纯 localStorage）
frontend/partner-demo.html           # 学生端伙伴自选

# 后端本地起
docker compose -f deploy/growth-planet-docker-compose.yml up -d gp-db
docker exec -i gp-db psql -U gp_app -d growth_planet < deploy/growth-planet-init.sql
cd server && cp ../deploy/.env.example .env && npm install && npm run dev

# 生产部署（服务器上）
git pull && bash deploy/build-frontend.sh \
  && docker compose -f deploy/growth-planet-docker-compose.yml up -d --build
```

> ⚠️ 改了 `server/` 才需要 `--build`；只改 `frontend/` 跑 `build-frontend.sh` 即可。
> ⚠️ 表结构有变更时，额外执行 `docker exec -i gp-db psql -U gp_app -d growth_planet < deploy/growth-planet-migrate.sql`。
