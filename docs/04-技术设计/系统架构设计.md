## 2. 关键架构决策（摘要，详见 [`架构决策记录ADR.md`](架构决策记录ADR.md)）

| 决策 | 选择 | 核心原因 |
|---|---|---|
| 前端形态 | **无框架的单文件 HTML** | 换电脑双击即用；弱网可用；无构建依赖；课堂上不能因为「npm 装不上」而挂掉 |
| 前端↔后端 | **同域（子域名）+ Nginx 反代 `/api/`** | 免 CORS/Cookie 问题；不与主站 `/api` 冲突 |
| 后端框架 | Fastify 5 | 轻、快、内置 JSON Schema 与日志；插件式鉴权钩子简洁 |
| 数据访问 | **裸 SQL + 参数绑定（无 ORM）** | 查询可读可调优；避免 ORM 抽象泄漏；项目规模不需要迁移框架 |
| 鉴权 | JWT（30 天）+ 自行实现的 `authenticate` 钩子 | 老师端只需「登录一次管一个月」；学生端接口显式不挂鉴权 |
| 学生端身份 | 免登录，凭 `student_id` | 小学生零门槛 |
| 数据隔离 | 独立 `gp-db` 容器 + 独立库 `growth_planet` | 不污染同机的 umami-db / MealPick 库 |
| 部署 | Docker Compose（2 容器）+ 宿主 Nginx | 与既有站点共存，不抢 80/443 |

## 4. 请求生命周期

```
浏览器 fetch('/api/...')
  → Nginx：location ^~ /api/ 命中 → proxy_pass http://127.0.0.1:3100（保留 /api 前缀）
  → Fastify：onRequest 钩子
       ├─ 需鉴权路由：app.authenticate → jwtVerify
       │     ├─ 通过 → 处理器执行（req.user.sub = teacher id）
       │     └─ 失败 → return reply.code(401).send({error:'未登录或登录已失效'})   ← 必须 return！
       └─ 免登录路由（/api/join/:code、/api/students/:id/claim、/api/students/:id/activity(s)）
  → 路由处理器
       ├─ assertUuid / assertText / assertInt 参数校验（400）
       ├─ assertOwnsClass / assertOwnsStudent 归属校验（404，不泄露存在性）
       ├─ query / withTx 访问 Postgres
       └─ reply.code(201).send(...)
  → 异常 → setErrorHandler：statusCode 或 500，5xx 打完整错误日志
  → 响应 JSON
```

## 5. 前端架构（云同步层）

前端不是「后端不可用就报废」的重前端，而是一个**渐进增强**结构：

```
teacher-dashboard.html
├── 纯本地模式（默认）
│   └── 数据存 localStorage（键 gp_classes / gp_current）
├── 云同步层 GP（当 window.GP_API_BASE 被注入为 '' 或 URL 时启用）
│   ├── GP.token / GP.teacher      ← localStorage 持久化
│   ├── GP.api(path, opts)         ← 统一 fetch + Authorization + 12s 超时
│   ├── GP.login() / pullAll()     ← 登录后拉取班级与状态
│   ├── remoteClassId() / remoteStudentId(i)  ← 本地索引 ↔ 云端 UUID 映射
│   └── refreshFromCloud() / cloudFail(err, msg)
└── 降级规则
    ├── GP_API 未注入 → GP_CLOUD = false，全程本地，不报错
    ├── 登录失败 → 保持本地模式，toast 提示
    └── 同步失败 → 数据仍在本机，明确提示「未同步，数据仍在本机」
```

> **构建时的坑**：源码用 `window.GP_API_BASE = '__GP_API_BASE__'` 作占位符，`build-frontend.sh` **只替换赋值语句**，不能全局替换——否则 `if(GP_API==='__GP_API_BASE__')` 也会被替换，导致 `GP_CLOUD` 恒为 false、登录按钮不显示（历史事故，提交 `fee26ac`）。

## 6. 性能设计

| 措施 | 说明 |
|---|---|
| 单文件前端 | 无外部 JS/CSS 请求；HTML 一次到手即可渲染 |
| Umami 延迟加载 | 统计脚本改为 `window.onload` 后动态注入，避免第三方 TTFB 拖慢首屏（历史事故：TTFB 2.46s 导致转圈） |
| 接口超时 | `GP.api()` 12s `AbortSignal`，避免请求悬挂导致界面假死 |
| 状态接口单次聚合 | `/state` 一次查询返回班级+学生+榜单+藤蔓，减少往返 |
| 索引 | `students(class_id)`、`events(class_id)`、`events(student_id)`、`vines(class_id)`、`student_activities(class_id/student_id)` |
| 轮询降频 | 15s 一次；页面隐藏时暂停 |
| 连接池 | pg Pool `max: 10`，`idleTimeoutMillis: 30s`，`connectionTimeoutMillis: 5s` |
| 慢查询告警 | `db.js` 中 > 500ms 打印 `[db] 慢查询` |

## 7. 安全设计

| 面 | 措施 |
|---|---|
| 传输 | 全站 HTTPS（Let's Encrypt，certbot 续期） |
| 认证 | JWT（HS256，`JWT_SECRET` ≥ 16 位，缺失直接启动失败） |
| 防枚举 | 登录对不存在的账号也执行 bcrypt 比较（恒定耗时），统一返回「邮箱或密码不正确」 |
| 越权 | 所有班级/学生操作强制 `assertOwnsClass` / `assertOwnsStudent` |
| SQL 注入 | 全部使用参数绑定（`$1,$2...`），无字符串拼接 |
| XSS | 前端输出统一经 `esc()` 转义 |
| 分值篡改 | 分值由服务端按 `label_key` 决定，客户端不可传分 |
| 刷分 | 签到按天去重；活动接口仅开放无害动作 |
| 密钥管理 | `.env` / `deploy/data/` / `deploy/frontend-built/` 全部在 `.gitignore` |
| 端口暴露 | gp-db 5434、gp-api 3100 均只绑 `127.0.0.1` |
| 请求体限制 | `bodyLimit: 256KB` |
| 隐私 | 仅存姓名 + 课堂行为；无手机号/头像/定位 |

## 8. 已知技术债

| 债 | 影响 | 偿还计划 |
|---|---|---|
| 无自动化测试 | 回归靠人工 | Phase 4 起补接口层集成测试（见 [`../05-研发流程与规范/研发流程规范.md`](../05-研发流程与规范/研发流程规范.md)） |
| 无 CI/CD | 部署靠手工执行命令 | 阶段性引入 GitHub Actions 做 lint + 构建校验 |
| 单文件 HTML 体积大（1400+ 行） | 可读性下降 | 暂不拆分（拆分需引入构建链，与「零依赖」冲突）；用注释分区强化结构 |
| 无数据库备份 | 误删不可回滚 | R35，Phase 3 落地 |
| 无错误上报（Sentry 类） | 线上问题靠日志排查 | 试用期先靠结构化日志 |
| `/state` 单次聚合查询较复杂 | 曾因 `GROUP BY` 出错 | 已修复并复核；后续如需扩展需注意聚合规则 |
