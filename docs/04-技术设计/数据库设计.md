## 1. ER 关系

```
                       ┌──────────────┐
                       │  teachers    │
                       │  (老师账号)   │
                       └──────┬───────┘
                              │ 1
                              │ teacher_id
                              ▼ N
                       ┌──────────────┐        ┌──────────────────┐
                       │  classes     │───────▶│   events         │
                       │  (班级/星球)  │  1   N │   (课堂点评)      │
                       │  class_code  │        │   delta / label  │
                       │  eco_value   │        └──────────────────┘
                       └──────┬───────┘
                              │ 1
                              │ class_id
                              ▼ N
   ┌────────────────────┐   ┌──────────────┐   ┌──────────────────────┐
   │  partner_claims    │◀──│  students    │──▶│  student_activities  │
   │  (认领记录)         │ N │  (学生/伙伴)  │ 1 │  (学生自主活动)       │
   └────────────────────┘   │  partner_kind│  N│  points/kind         │
                            │  vitality    │   └──────────────────────┘
                            └──────┬───────┘
                                   │ a_id / b_id
                                   ▼
                            ┌──────────────┐   ┌──────────────┐
                            │   vines      │   │ submissions  │
                            │  (关系藤蔓)   │   │ (作业提交，预留)│
                            └──────────────┘   └──────────────┘
```

**关系说明**
- `teachers 1—N classes`：老师拥有多个班级（`ON DELETE CASCADE`）
- `classes 1—N students`：班级包含学生（`ON DELETE CASCADE`）
- `students 1—N events`：学生的点评记录（`ON DELETE SET NULL`，保留行为历史）
- `students 1—N student_activities`：学生的自主活动（`ON DELETE CASCADE`）
- `students N—N students`（经 `vines`）：同学之间的合作关系，唯一约束限定一对学生一条
- `classes 1—N events/student_activities/vines`：按班级维度查询与级联清理

## 2. 表结构

### 2.1 `teachers` — 老师账号

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK, `gen_random_uuid()` | |
| email | TEXT | UNIQUE, NOT NULL | 登录名，存小写 |
| password_hash | TEXT | NOT NULL | bcrypt（cost=10） |
| display_name | TEXT | | 显示名，如「李老师」 |
| created_at | TIMESTAMPTZ | DEFAULT now() | |

### 2.2 `classes` — 班级（生态星球）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | |
| teacher_id | UUID | NOT NULL, FK → teachers, CASCADE | 归属老师 |
| name | TEXT | NOT NULL | 班级名（≤30 字，服务端校验） |
| grade | INT | 可为空 | 1–6 |
| theme | TEXT | 可为空 | 自定义主题词 |
| theme_pack | TEXT | 可为空 | `cute_nature` / `life_obs` / `anime_original` |
| stage | TEXT | DEFAULT 'wild' | 历史字段（阶段现由 `eco_value` 实时推算） |
| eco_value | INT | DEFAULT 0 | 班级生态值，只累加正向 |
| **class_code** | TEXT | UNIQUE（迁移新增） | 入班码 = id 前 6 位十六进制 |
| created_at | TIMESTAMPTZ | DEFAULT now() | |

> **`class_code` 生成规则**：建班时 `LEFT(REPLACE(id::text,'-',''), 6)`（`classes.js:73`），天然唯一且无需额外随机源；重置时用 `gen_random_uuid()` 前 6 位（`classes.js:105`）。查询时统一 `trim().toLowerCase()`。

### 2.3 `students` — 学生与其伙伴

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | 学生端凭此 id 免登录写入 |
| class_id | UUID | NOT NULL, FK → classes, CASCADE | |
| name | TEXT | NOT NULL | 真实姓名 |
| **nickname** | TEXT | （迁移新增） | 学生自定义昵称（学生端显示） |
| **color** | TEXT | （迁移新增） | 主色 `#RRGGBB`（伙伴发光色） |
| group_name | TEXT | 可为空 | 小组名（用于「最繁荣小组」榜规划） |
| sort_order | INT | 可为空 | 花名册顺序 |
| partner_kind | TEXT | 可为空 | 38 种伙伴之一（`PARTNER_KINDS` 白名单） |
| partner_stage | INT | DEFAULT 0 | 0–3，由 growth 推算（阈值 `[0,12,35,70]`） |
| vitality | INT | DEFAULT 50 | 0–100 |
| loved | BOOLEAN | DEFAULT false | 被爱护标记 |
| hurt | BOOLEAN | DEFAULT false | 受伤标记（负向 `hurt_life` 触发，可照料恢复） |
| created_at | TIMESTAMPTZ | DEFAULT now() | |

### 2.4 `events` — 课堂点评

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | 用于撤销 |
| class_id | UUID | NOT NULL, FK → classes, CASCADE | |
| student_id | UUID | FK → students, **SET NULL** | 删学生保留行为历史 |
| teacher_id | UUID | NOT NULL, FK → teachers | 撤销时校验本人 |
| label_key | TEXT | NOT NULL | 12+3 标签之一（`labels.js`） |
| delta | INT | NOT NULL | 分值快照（由服务端写入，不随标签改动而回溯） |
| created_at | TIMESTAMPTZ | DEFAULT now() | 用于「今日得分」统计 |

> **为什么存 `delta` 快照而不是只存 `label_key`？** 标签分值是会随教学策略调整的（例如把「完整表达结论」从 +3 调到 +4）。存快照可保证历史评分的解释性与可审计性；同时 `events` 表的 `SUM(delta)` 是成长值的唯一权威来源。

### 2.5 `student_activities` — 学生自主活动（Phase 2 新增）

## 4. 核心查询与聚合规则（易错点）

### 4.1 全班状态聚合（`events.js:124`）

```
students s
  LEFT JOIN ( events 按 student_id 聚合 → g )        ON g.student_id = s.id
  LEFT JOIN ( student_activities 按 student_id 聚合 → a ) ON a.student_id = s.id
WHERE s.class_id = $1
```

**规则**：
- 第一段查询**无 GROUP BY**（`s` 与两个已聚合子查询按行连接），`a.act_points` 直接取值即可；
- 第二段「光荣榜」查询因为要对 `events` 做 `SUM/COUNT` 聚合，**必须 GROUP BY**，因此所有来自 `a` 子查询的列**必须包在聚合函数里**，否则 Postgres 报：

```
ERROR 42803: column "a.act_points" must appear in the GROUP BY clause
             or be used in an aggregate function
```

- **正确写法**：`COALESCE(MAX(a.act_points), 0)::INT`（`a` 子查询按 `student_id` 分组后每人只有一行，`MAX` 等价取值）；
- **反面写法**：`COALESCE(a.act_points, 0)` ← **这是导致「批量导入学生失败」的线上事故根因（R25）**。

> 维护提示：以后给这两段查询加字段时，先判断该查询有没有 `GROUP BY`。有 `GROUP BY` 的必须聚合。

### 4.2 成长值（growth）口径

```
growth(学生) = SUM(events.delta WHERE student_id = 学生)
             + SUM(student_activities.points WHERE student_id = 学生)
```

- `events.delta` 由老师点评产生；`student_activities.points` 由学生自主活动产生；
- 两者相加后决定 `partner_stage`（`stageOf(growth)`）；
- 学生端「我的伙伴」的等级用 `Math.floor(total/5)+1`（`partner-demo.html:553`），与 `partner_stage` 是两套显示口径。

### 4.3 今日得分

`SUM(delta) FILTER (WHERE created_at >= date_trunc('day', now()))` —— 使用数据库时区（容器默认 UTC，注意与北京时间差 8 小时，日界统计会有偏差，属已知待改进项）。

## 5. 迁移策略

| 场景 | 操作 |
|---|---|
| **全新建库** | `docker exec -i gp-db psql -U gp_app -d growth_planet < deploy/growth-planet-init.sql` |
| **已有库升级** | `docker exec -i gp-db psql -U gp_app -d growth_planet < deploy/growth-planet-migrate.sql` |

**迁移脚本编写规范**：
1. 必须**幂等**：`CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` / `DROP CONSTRAINT IF EXISTS`；
2. 只做**增量**：不改动已有列的类型与语义；
3. 必须**同时**更新 `init.sql`（保证新装环境与迁移后环境一致）；
4. 每条迁移加编号注释与说明，注明解决什么问题；
5. 执行前先备份：`docker exec gp-db pg_dump -U gp_app growth_planet > backup_$(date +%F).sql`。

## 6. 备份与恢复（当前状态与计划）

**当前**：仅有 Docker 卷 `deploy/data/postgres`，**无定时备份**（风险 RK-03 / 需求 R35）。

**计划落地（Phase 3）**：

```bash
# /etc/cron.d/gp-backup  —— 每日 03:30 备份，保留 14 天
30 3 * * * root docker exec gp-db pg_dump -U gp_app -Fc growth_planet \
  > /opt/backups/gp/growth_planet_$(date +\%F).dump \
  && find /opt/backups/gp -name '*.dump' -mtime +14 -delete

# 恢复演练（每季度一次）
docker exec -i gp-db pg_restore -U gp_app -d growth_planet --clean < growth_planet_2026-09-11.dump
```
