## INC-001 页面 JS 全部泄露为文本，按钮全失效

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-07 |
| 提交 | `7ac1df7` |
| 严重度 | 高（页面完全不可用） |

**现象**：打开老师端，主区域空白，页面底部出现大段 JS 源码文本，所有按钮点击无反应。

**排查**：查看渲染后的 DOM，发现 `<script>` 提前闭合——JS 源码被当成 body 文本渲染。

**根因**：JS 注释中写了 `</script>`（在说明「在本文件 `<script>` 之前加一行」时直接写了该标签）。HTML 解析器在遇到注释里的 `</script>` 时**仍然会结束 script 元素**（HTML 的脚本数据状态不解析 JS 注释），导致后续代码全部落到 HTML 文本节点。

**修复**：把注释中的 `</script>` 改写为 `<\/script>`（转义斜杠）。

**验证**：页面正常渲染，所有按钮可用。

**预防**：
1. 在 HTML 内联 JS 中，**任何要显示 `</script>` 字样的地方必须写成 `<\/script>`**；
2. 已写入开发自检清单（[`../05-研发流程与规范/研发流程规范.md §3.1`](../05-研发流程与规范/研发流程规范.md)）；
3. 部署后必须打开页面看一眼（不能只看接口 200）。

## INC-002 登录按钮不显示

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-06 |
| 提交 | `fee26ac` |
| 严重度 | 高（无法登录） |

**现象**：部署后无痕窗口打开，右下角「☁ 登录同步」按钮不显示。

**根因**：`deploy/build-frontend.sh` 使用 sed **全局替换** `__GP_API_BASE__`。除了预期的赋值语句：

```js
window.GP_API_BASE = '__GP_API_BASE__';   // 想改成 ''
```

检查语句也被替换了：

```js
if (GP_API === '__GP_API_BASE__') GP_API = null;   // 被替换成 if (GP_API === '') GP_API = null;
```

结果 `GP_CLOUD` 计算错误 → 判断为「未配置云端」→ 登录入口不渲染。

**修复**：sed 表达式收窄为**只匹配赋值语句**：

```bash
sed "s/window\.GP_API_BASE *= *'__GP_API_BASE__'/window.GP_API_BASE = '${API_BASE}'/g" "$SRC/$f" > "$OUT/$f"
```

**验证**：构建产物中 `if(GP_API==='__GP_API_BASE__')` 保持原样，登录按钮显示且可登录。

**预防**：
1. 构建脚本中的替换必须**精确匹配**，禁止宽泛的全局替换；
2. 已在 `build-frontend.sh` 内写入注释说明「不要用全局替换」；
3. 部署验收清单加入 0.7「前端占位符已注入」检查项。

## INC-003 老师大屏长时间转圈打不开

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-10 |
| 提交 | `6e28c34` |
| 严重度 | 高（进不去） |

**现象**：用户反馈「网站用着用着打不开，一直转圈」。

**排查**：DevTools Network 面板看到 `analytics.mealpick.me/script.js` 的 **TTFB 高达 2.46s**，且该脚本带 `defer`，页面 `load` 事件被拖到 2.5s 之后；同时业务接口无超时设置，一旦悬挂界面无任何反馈，表现为「一直转圈」。

**根因**：**第三方统计脚本阻塞首屏** + **接口无超时** + **加载期间无任何可视化提示**，三个问题叠加。

**修复**：
1. Umami 脚本改为 `window.onload` 之后动态注入，加载失败不影响业务；
2. `GP.api()` 加 12 秒 `AbortSignal` 超时；
3. 初始化显示「正在加载星球…」提示，失败时 toast 明确原因。

**验证**：首屏 3 秒内可交互；Network 中统计脚本在 `load` 之后请求。

**预防**：
1. **任何第三方脚本一律延迟加载**，不得位于关键渲染路径；
2. 所有 `fetch` 必须带超时；
3. 长任务前必须有可见的 loading 态；
4. 已写入自检清单（前端第三条）。

## INC-004 删除学生 / 班级返回 500

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-10 |
| 提交 | `329dc66` + 迁移脚本第 4 节 |
| 严重度 | 中（可绕过，但影响老师维护花名册） |

**现象**：老师端删除学生报 500。

**排查**：`docker logs gp-api` 显示外键约束违反。

**根因**：`partner_claims` 与 `submissions` 两表引用 `students(id)` 时**漏写 `ON DELETE CASCADE`**，删除学生被外键阻塞。这两个表的 `init.sql` 里已经写对了，但**生产库是先建表后补的**，历史表结构的约束没跟上。

**修复**：迁移脚本中重建外键：

```sql
ALTER TABLE partner_claims DROP CONSTRAINT IF EXISTS partner_claims_student_id_fkey;
ALTER TABLE partner_claims ADD CONSTRAINT partner_claims_student_id_fkey
  FOREIGN KEY (student_id) REFERENCES students(id) ON DELETE CASCADE;
-- submissions 同理
```

**验证**：线上删除学生返回 204，关联数据一并清除。

**预防**：
1. **外键必须显式声明删除策略**（`CASCADE` / `SET NULL`），不允许默认 `NO ACTION`；
2. 迁移脚本编写时必须同时更新 `init.sql`，保证「新装环境」与「升级后环境」表结构一致；
3. 删除类操作必须纳入验收清单（3.7 / 2.7）。

## INC-005 登录返回 Internal Server Error

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-11 |
| 提交 | `91feb29` |
| 严重度 | 高（完全无法使用） |

**现象**：老师登录界面显示 `Internal Server Error`（纯文本，非 JSON）。日志中 `POST /api/auth/login` 返回 **200**，但紧随其后的接口出现异常。

**排查过程（关键：先读日志，不盲改）**：

```bash
docker logs --tail 80 gp-api
```

日志显示登录本身 **200 正常**，但 `/api/classes` 之后的链路异常；进一步用 curl 直连验证：

```bash
# 登录 OK，拿到 token
curl -sS -X POST https://gp.mealpick.me/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"luyulin@mealpick.me","password":"yourPassword123"}'   # → 200 + token

# 但带 token 访问受保护接口 → 401「未登录或登录已失效」
curl -sS -i https://gp.mealpick.me/api/classes -H "Authorization: Bearer $TOKEN"
```

**根因**：`server/src/index.js` 的鉴权钩子：

```js
app.decorate('authenticate', async (req, reply) => {
  try {
    await req.jwtVerify();
  } catch (err) {
    reply.code(401).send({ error: '未登录或登录已失效' });   // ← 缺少 return！
  }
});
```

Fastify 中钩子调用 `reply.send()` 后**不会自动中断后续处理**：钩子返回后，路由处理器仍会执行，此时 `req.user` 为 `undefined`，访问 `req.user.sub` 抛 `TypeError`，被 `setErrorHandler` 兜成 **500 纯文本**——与截图表现完全一致。

**修复**：

```js
  } catch (err) {
    // 必须 return，否则钩子放行后处理器仍会执行、取 req.user 抛错变成 500
    return reply.code(401).send({ error: '未登录或登录已失效' });
  }
```

同时加固前端：`GP.login()` 中的 `pullAll()` 包 try/catch，避免「登录成功但同步失败」被误报为登录失败。

**验证**：
- 错误密码 → **401**（不再是 500）；
- 正确密码 → 200 + token，受保护接口 200。

**预防**：
1. **Fastify 钩子中任何 `reply.send()` 必须 `return`**（已写入 [`../05-研发流程与规范/代码与提交规范.md §2.2`](../05-研发流程与规范/代码与提交规范.md)）；
2. 登录链路必须测「错误凭据」路径，验收清单 0.3 / 1.4 已固化；
3. 排查顺序固定为：**读日志 → 定位文件行 → 一次改好 → 复验**；本次排障过程中出现过一个反面操作：在 shell 里用 `sed 's/.*"token":"$[^"]*$".*/\1/'` 抓 JSON，因转义问题报 `invalid reference \1` —— 正确做法是用 `node -e` / `python -c` 解析 JSON（已记入 [`../04-技术设计/API接口文档.md §3.1`](../04-技术设计/API接口文档.md)）。

## INC-006 批量导入学生提示失败（`act_points` 聚合错误）

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-11 |
| 提交 | 4fd168d |
| 严重度 | 高（老师无法维护花名册） |

**现象**：老师端「花名册」导入 3 个名字（孙少奇 / 陈定涛 / 张卫良）后，界面提示「**导入失败：Internal Server Error**」，且顶部 toast 显示「添加未同步，数据仍在本机」。

**排查过程**：

```bash
docker logs --tail 80 gp-api
```

日志关键片段：

```
req-8  POST /api/classes/d9e1b6d8-.../students   → 201   ← 新增其实成功了！
req-9  GET  /api/classes/d9e1b6d8-.../state      → 500
       DatabaseError: column "a.act_points" must appear in the GROUP BY clause
                      or be used in an aggregate function
       at .../src/routes/events.js:153
       code: 42803
```

**根因**：`server/src/routes/events.js` 的「光荣榜」查询（`boardRows`）：

```sql
SELECT s.id, s.name,
       (COALESCE(SUM(e.delta), 0) + COALESCE(a.act_points, 0))::INT AS growth,   -- ← 问题在这
       ...
  FROM students s
  LEFT JOIN events e ON e.student_id = s.id AND e.class_id = $1
  LEFT JOIN ( SELECT student_id, SUM(points)::INT AS act_points
                FROM student_activities WHERE class_id = $1 GROUP BY student_id ) a
         ON a.student_id = s.id
 WHERE s.class_id = $1
 GROUP BY s.id, s.name
```

该查询含 `GROUP BY s.id, s.name`，而 `a.act_points` 既不在 `GROUP BY` 中、也没有被聚合函数包裹 → Postgres 报 `42803`。

> 为什么第一段 `studentRows` 查询没报错？因为**它没有 `GROUP BY`**（`s` 与两个已聚合子查询做行连接），非聚合列可以直接取。第二段为了算 `SUM/COUNT` 必须 `GROUP BY`，规则就变了。这个差异是本次踩坑的关键。
>
> 另外：`a.act_points` 之所以存在，是因为 Phase 2 新增了「把学生自主活动积分并入成长值」的功能（提交 `04e4225`），改动时只验证了第一段查询（老师大屏首屏能打开），**没有验证第二段聚合查询**——而它恰好在每次导入学生后的自动刷新时被触发。

**为什么显示成「导入失败」**：学生其实已成功入库（201）。前端 `importBatch()` 把 `POST /students` 与 `refreshFromCloud()` 串在同一个 `.catch` 里，刷新失败被当成导入失败 → **错误提示误导了老师**（老师会以为数据没进去，从而重复导入）。

**修复**：
1. 后端：改为 `COALESCE(MAX(a.act_points), 0)::INT`（`a` 子查询按 `student_id` 分组后每人仅一行，`MAX` 等价取值，且满足聚合要求）：

```sql
(COALESCE(SUM(e.delta), 0) + COALESCE(MAX(a.act_points), 0))::INT AS growth,
```

2. 前端：把「新增」与「刷新」的成功判定拆开：

```js
GP.api('/api/classes/'+remoteClassId()+'/students',{method:'POST',body:JSON.stringify({names:fresh})})
  .then(()=>refreshFromCloud()
    .then(()=>{ /* 提示：已导入 N 位 */ })
    .catch(()=>{ /* 提示：已导入 N 位，但花名册刷新超时，请手动刷新页面 */ }))
  .catch(err=>{ /* 提示：导入失败 */ });
```

**验证**（2026-09-11 服务器已验证）：

```bash
CID=$(curl -sS https://gp.mealpick.me/api/classes -H "Authorization: Bearer $TOKEN" \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).classes[0].id))")
curl -sS -o /dev/null -w '%{http_code}\n' "https://gp.mealpick.me/api/classes/$CID/state" -H "Authorization: Bearer $TOKEN"
# 结果：200（此前为 500）✅ 导入后自动刷新不再报错，导入提示正常
```

**预防**（本期已固化）：
1. **SQL 规则**：凡含 `GROUP BY` 的查询，SELECT 中的每一个非聚合列都必须出现在 `GROUP BY` 里，或包在聚合函数内。已写入 [`../04-技术设计/数据库设计.md §4.1`](../04-技术设计/数据库设计.md#41-全班状态聚合eventsjs124) 与开发自检清单；
2. **改动聚合查询时必须整体验证**：`/state` 有两段聚合查询，改一段必须同时跑另一段；
3. **接口层最小集成测试（Phase 4 首要补测项）**：`/state` 的聚合查询正是历史两次踩坑点（外键、聚合），必须纳入自动化；
4. **前端错误提示必须准确划分阶段**：区分「请求失败」与「刷新失败」，禁止用一个 `.catch` 吞掉不同阶段的错误——错误提示不准确本身就是一个缺陷；
5. 部署后冒烟必须包含 `GET /api/classes/:id/state`（验收清单 0.6）。
