# 课堂点评与学生互动闭环设计

> 本文回答两个问题：**① 老师端的两步点评链路是怎么设计的？② 学生端与伙伴的互动闭环是怎么设计的？**
> 并补充一条此前只在代码里存在、没有文档的功能说明：[3.2 关系藤蔓网怎么用](#32-关系藤蔓网怎么用)。

---

## 1. 设计目标

| 目标 | 具体指标 | 设计手段 |
|---|---|---|
| 不打断教学 | 单次点评 ≤ 3 秒 | 两步点击，无弹窗、无确认、无键盘输入 |
| 反馈要「当场」 | 点击后 < 300ms 出动画 | 前端先本地乐观渲染特效，再落库 |
| 公平可信 | 分值不可被前端篡改 | 分值由服务端按 `label_key` 映射 |
| 可纠错 | 点错可一键撤销 | `DELETE /api/events/:id` 事务回滚 |
| 不羞辱 | 负向不进榜、可恢复 | 负向标签独立分组 + `care` 照料接口 |
| 课后不断联 | 学生可自主积累成长值 | 免登录活动接口 + 服务端定分 + 每日去重 |

## 2. 老师端：两步点评链路

### 2.1 流程图

```
[大屏已加载 /api/classes/:id/state]
        │
        │ 老师点击某个学生的伙伴卡片
        ▼
   selectedId = i          ← 伙伴进入 sel 状态（外发光）
        │
        │ 底部 dock 出现该学生可用的标签分组
        ▼
   老师点击某个标签（label_key）
        │
        ├─(乐观渲染) 立刻播放对应 fx 特效 + 伙伴 hop  ──────┐
        │                                                  │
        └─ POST /api/events {class_id, student_id, label_key[, partner_id]}
                 │                                         │
                 ▼                                         │
         服务端（事务 withTx）                              │
           1. INSERT events (delta = label.delta)          │
           2. 重算该生 growth = SUM(delta)                 │
           3. UPDATE students: vitality、partner_stage、    │
                              hurt、loved                  │
           4. 若 label.vine 且带 partner_id → 写 vines     │
           5. 若 delta > 0 → classes.eco_value += delta     │
                 │                                         │
                 ▼                                         │
         返回 201 { event, student, fx, class_stage } ──────┘
                 │
                 ▼
         前端用返回的真实数据校正 UI（防乐观渲染漂移）
```

### 2.2 关键设计决策

| 决策 | 理由 |
|---|---|
| `partner_id` 可选，用于合作类标签 | 「小组合作探究」需要指定合作对象才能长藤蔓 |
| 不接受前端传分值 | 防刷分；前端只能传 `label_key`（白名单校验） |
| 协作对象不能是自己 | `if (partnerId === studentId) throw` |
| 事务内重算 growth | 避免增量累加导致的漂移；用 `SUM(delta)` 保证可自愈 |
| 负向标签 `eco: 0` | 班级生态是正向激励，不能被负向拖累 |
| 撤销时 `GREATEST(0, eco_value - delta)` | 生态值不允许为负 |
| 前端乐观渲染 + 服务端校正 | 保证「当场有反馈」的体感，同时以服务端为准 |

### 2.3 状态与特效映射

| label_key | fx | 伙伴状态变化 |
|---|---|---|
| `ask_question` | bloom | vitality +6 |
| `conclude` / `engineering` / `persist_observe` | evolve | vitality +9 |
| `safe_op` / `safety_remind` | glow | vitality +6（safety_remind 额外长藤蔓） |
| `observe` / `reading` | leaf | vitality +6 / +3 |
| `love_life` | hug | vitality +9，`loved = true` |
| `cooperate` / `help_mate` | vine | vitality +6，长藤蔓 |
| `tidy_up` | tidy | vitality +6 |
| `unsafe_act` / `hurt_life` / `untidy` | droop / hurt / mess | vitality −6 / −9 / −3，`hurt_life` 置 `hurt = true` |

## 3. 学生端：伙伴互动闭环

### 3.1 闭环结构

```
        ┌──────────────── 认领 ────────────────┐
        │  输班级码 → 选名字 → 浏览图鉴 → 点卡片认领  │
        └───────────────────┬──────────────────┘
                            ▼
                    「我的伙伴」主页
             （动画伙伴 + 生态值进度 + 活动列表）
                            │
      ┌─────────────────────┼─────────────────────┐
      ▼                     ▼                     ▼
  🌞 每日签到           📚 课间答题            🔍 观察记录
  checkin  +1           quiz  +2(答对)         observe  +1
  每日仅一次             答错 +0，仍记录        可填内容摘要
                            │
                            ▼
                  POST /api/students/:id/activity
                  （免登录；分值服务端定；防作弊）
                            │
                            ▼
               student_activities 表 → SUM(points)
                            │
       ┌────────────────────┴────────────────────┐
       ▼                                          ▼
  学生端：生态值进度条前进、伙伴 hop 反馈     老师大屏：15s 轮询
                                             growth = events + activities
```

### 3.2 关系藤蔓网怎么用

> 这条功能从 Phase 1 就存在于代码里（`vines` 表 + 大屏 SVG 连线 + 「最佳搭档」卡片），但一直**没有面向老师的说明**。补在这里。

**是什么**：当老师给一次「合作类」点评并指定了合作对象时，两位同学之间会长出一条藤蔓；藤蔓只表示「他们合作过」，不表示亲疏好坏，也不排名。

**哪三个标签会长藤蔓**（`labels.js` 中 `vine: true`）：

| 标签 | 场景举例 |
|---|---|
| 🤝 小组合作探究 | 「小A 和小B 一起搭斜面，配合得很好」 |
| 💚 帮助同学 / 分享发现 | 「小C 把放大镜借给小D，还讲了用法」 |
| 🛡 安全提醒 / 保护同伴 | 「小E 提醒小F 别用手直接碰加热后的烧杯」 |

**操作步骤**（老师端）：

1. 点一个学生的伙伴 → 选中；
2. 在底部 dock 点到 **🤝 小组合作探究** 这类带藤蔓的标签；
3. 弹出协作对象选择 → 点另一位学生的伙伴；
4. 提交。两位的伙伴之间立刻出现一条藤蔓，星球区与「关系藤蔓网」卡片同步更新。

**在大屏上怎么看**：

- 星球区：两位伙伴之间画出绿色连线（`#vines` SVG 层）；
- 右侧面板「🌿 关系藤蔓网」：显示与该生相连的伙伴名单与数量；
- 光荣榜「🤝 最佳搭档」卡片：藤蔓最多的那一对。

**规则与边界**：

- 同一对学生之间**只保留一条藤蔓**（`vines` 表 `UNIQUE(class_id, a_id, b_id)`，重复合作 `ON CONFLICT DO NOTHING`）；
- 藤蔓不带分值、不影响生态值（生态值只由标签 `delta` 决定）；
- 删除学生会级联删除其藤蔓；
- 一条「安全提醒」也能长藤蔓——设计意图是**把亲社会行为也可视化**，不只是成绩。

**教学用法建议**：每周换一次座位后，看看「关系藤蔓网」里有没有总是和固定两三个人连线的孩子；鼓励他们和没连过线的同学合作一次，让关系网更密。

### 3.3 学生端计分表

| 活动 | kind | 分值 | 限制 | 备注 |
|---|---|---|---|---|
| 每日签到 | `checkin` | +1 | 每日一次（服务端按 `date_trunc('day', now())` 去重） | 重复签到返回 `already: true` + 「今天已经签到啦」 |
| 课间答题 | `quiz` | 答对 +2 / 答错 0 | — | **题库待补（R33）**，当前为占位交互 |
| 观察记录 | `observe` | +1 | — | 可填内容摘要（≤200 字） |
| 提交作业 | `homework` | +3 | — | 接口已就绪，**学生端按钮未放（R32）** |

**防作弊设计**：分值完全由服务端的 `kind` 决定，客户端只能传 `kind` / `detail` / `correct`；即使伪造 `correct: true` 也最多拿 2 分（这是「答题」，本身无标准答案可校验，等题库上线后改由服务端判卷）。

## 4. 老师端实时性设计

| 机制 | 实现 |
|---|---|
| 轮询频率 | 15 秒一次 `POST?` → `GET /api/classes/:id/state` |
| 后台暂停 | `document.visibilityState === 'hidden'` 时暂停轮询，回到前台立即拉一次 |
| 变化反馈 | 生态值增加时，伙伴播放 `hop` 动画，让「有人在互动」被看见 |
| 网络韧性 | `GP.api()` 带 12s `AbortSignal` 超时；失败不打断界面，仅 toast 提示 |
| 首屏 | Umami 延迟到 `window.onload` 异步加载；初始化显示「正在加载星球…」 |

## 5. 已知缺口与收口计划

| 缺口 | 影响 | 计划 |
|---|---|---|
| 课间答题无真实题库 | 「总结知识点问答」需求只完成了一半 | Phase 4：新增 `questions` 表 + 服务端判分（R33） |
| 学生端无「提交作业」按钮 | 老师无法布置、学生无法提交 | Phase 4（R32） |
| 老师端看不到学生互动明细 | 老师只知道「成长值涨了」，不知道「做了什么」 | Phase 4：`GET /api/classes/:id/activities` + 点击学生卡片弹侧栏（R34） |
| 标签与「当堂知识点」未挂钩 | 无法按课时推荐标签 | Phase 4（R30 收口） |
