## 0. 设计基线（开工前必读）

### 0.1 设备与场景

| 角色 | 设备 | 最小宽度 | 断点策略 |
|---|---|---|---|
| 老师 | 智慧白板 / 笔记本投影 | 1366px | 桌面优先，1366 / 1100 / 768 三断点（已有） |
| 学生（课间） | 平板 / 手机 | 320px | 移动优先，576 / 768 渐进增强 |

### 0.2 视觉系统（沿用现有）

- **主色**：霓虹绿 `#2ecc71`（成长/正向）
- **中性色**：深空渐变 `#0f172a → #1e293b`（背景）
- **语义色**：成功 `#22c55e` / 警告 `#f59e0b` / 错误 `#ef4444` / 信息 `#3b82f6`
- **字体**：系统无衬线，8px 基线刻度（12 / 14 / 16 / 20 / 24 / 32 / 48）
- **圆角**：卡片 16px，按钮 10px，输入 8px
- **动效**：0.2-0.3s，仅 `transform` + `opacity`

### 0.3 无障碍基线（WCAG 2.2 AA）

- 正文对比度 ≥ 4.5:1，大字 / UI 边框 ≥ 3:1
- 键盘可达：Tab 序列逻辑清晰，焦点可见（`focus-visible`）
- 语义化 HTML 优先于 ARIA 兜底
- 禁用「仅以颜色传达状态」——状态变更必须配文字或图标

## 一、P0 — 核心需求（必须先做）

### R62 大屏「今日亮点 / 进步之星」默认位

- **需求来源**：PRD R03 差距——默认展示「今日亮点」而非总榜
- **设计目标**：把「去排名」做实，光荣榜退为次级
- **设计要点**：
  1. 大屏光荣榜区**前置**一个「✨ 今日亮点」卡片（默认展示位）
  2. 老师两步点击即可标记某学生当日亮点行为（点伙伴 → 「设为今日亮点」标签）
  3. 卡片内容：学生头像 + 亮点行为文案 + 时间 + 小伙伴陪伴动画
  4. 多人亮点：横滑列表，最新一条居中放大
  5. 当日无亮点时：展示「今天还没有亮点，期待你的发现」空态 + 引导箭头指向花名册
- **交互**：标记后 3 秒内大屏伙伴 `hop` + 粒子放大（复用 R56 的 `spawnSpark`）
- **无障碍**：卡片有 `aria-label="今日亮点：{学生名}，{行为}"`；键盘可达标记按钮
- **验收**：大屏默认展示今日亮点而非总榜；老师标记 → 3 秒反馈；空态文案清晰

### R63 伙伴状态正向化改造

- **需求来源**：PRD R05 差距——禁用 `droop/hurt` 负面表达
- **设计目标**：把「蔫了/受伤」改成「伙伴想你了」式正向召唤
- **设计要点**：
  1. 状态文案表（后端 + 前端同步）：
     | 旧状态 | 新文案 | 视觉表现 |
     |---|---|---|
     | `droop` | 「伙伴想晒太阳了」 | 伙伴微微低头 + 头顶出现小太阳图标（可点击「带它去晒」） |
     | `hurt` | 「伙伴等你回来」 | 伙伴坐在小凳子上张望 + 头顶信封图标 |
     | 离线 ≥3 天 | 「伙伴想你了」 | 信封轻微抖动 + 「戳一下」按钮 |
  2. 负向标签 `delta` 不再为负——改为「正向分暂时搁置，不倒扣」（架构层禁止减法）
  3. 「带它去晒 / 戳一下」是正向恢复入口，点击后伙伴 `bloom` 动画 + 活力回 50+
- **交互**：状态切换用 `opacity` 渐变（0.3s），不用硬切
- **无障碍**：状态文案是文字非图标，屏幕阅读器可读；恢复按钮有 `aria-label`
- **验收**：全界面无「蔫了/受伤/枯萎」字样；离线 3 天自动召唤；负向不扣分

### R64 监护人知情同意书模板

- **需求来源**：PRD R10 差距——试点前置条件
- **设计目标**：一份可打印、可签字、面向家长的合规文档
- **设计要点**：
  1. 独立页面 `frontend/consent.html`（A4 单页，`@media print` 优化）
  2. 7 个章节：采集什么 / 不采集什么 / 数据用途 / 保存期限 / 删除权 / 未成年人保护 / 联系方式
  3. 底部签字区：监护人签字栏 + 日期 + 学生姓名 + 班级
  4. 老师端入口：花名册浮层「📄 知情同意书」按钮 → 新窗口打开 → 浏览器打印
  5. 版本号 + 生效日期 + 学校 / 班级占位符（老师自行填写）
- **交互**：打印按钮 `window.print()`；Esc 关闭窗口
- **无障碍**：正文字号 ≥ 12pt，对比度 ≥ 4.5:1；签字栏有 `label`
- **验收**：可打印 A4 单页；7 章节齐全；签字栏清晰

### R66 AI 出题简化版

- **需求来源**：PRD R06——闭环 B 核心
- **设计目标**：老师粘贴教学要点 → 60 秒内出 8-12 题
- **设计要点**：
  1. 录题面板新增「🤖 AI 出题」折叠区（在 R59 批量导入旁）
  2. 文本框：教学要点（≤500 字，`maxlength` + 字数计数器）
  3. 选项：年级 / 题量（8 / 10 / 12）/ 难度（基础 / 进阶）
  4. 「生成」按钮：Loading 态（骨架屏 6-8 个题目占位卡片，旋转图标）
  5. 生成后：题目卡片列表，每题可「✏️ 编辑 / 🗑️ 删除 / 🔄 重生成」
  6. 底部「📥 全部入库」按钮 → 批量写入题库
  7. 失败态：「生成超时，请检查教学要点或重试」+ 重试按钮（不丢已输入的要点）
- **交互**：生成中按钮 `disabled` + `aria-busy="true"`；骨架屏 stagger 80ms 入场
- **无障碍**：文本框 `aria-label="教学要点"`；按钮有 `aria-label`；错误提示 `role="alert"`
- **验收**：60 秒内返回题目；可编辑 / 删除 / 重生成；批量入库成功

### R77 注册开关前端可见性（待修 Bug）

- **需求来源**：Bug 排查——`ALLOW_REGISTER=false` 时注册按钮仍可见，点了报错
- **设计目标**：前端动态显隐注册入口，避免用户点了才报错
- **设计要点**：
  1. 登录弹窗 `openLogin()` 时先调 `GET /api/auth/allow-register`（新增轻量接口）返回布尔
  2. `true` → 显示「注册新账号」入口；`false` → 隐藏 + 登录弹窗底部加一行「账号开通请联系管理员」小字
  3. 或复用 `/api/me` 的元数据返回（已登录用户无影响）
  4. 入口隐藏用 `hidden` 属性（非 `display:none`），保证屏幕阅读器也跳过
- **交互**：接口请求用 `AbortSignal`（3 秒超时），超时默认隐藏（安全优先）
- **无障碍**：隐藏的入口 `aria-hidden="true"` + `tabindex="-1"`
- **验收**：`ALLOW_REGISTER=false` 时无注册入口；`true` 时正常显示

### R78 学生端选主色实时视觉反馈（待修 Bug）

- **需求来源**：Bug 排查——选主色后伙伴无变化，颜色只进被遮罩柔化的 drop-shadow
- **设计目标**：选色时伙伴预览立即可见主色调
- **设计要点**（三选一，倾向方案 C）：
  | 方案 | 改动 | 效果 | 影响范围 |
  |---|---|---|---|
  | **C. 光环反馈**（推荐） | 选中色板时 `.aura` 背景色实时改为 `--c` | 选色有光环颜色变化，PNG 不动 | `renderSwatches()` + CSS |
  | D. PNG 叠 tint 层 | 给 `<img>` 叠 `mix-blend-mode` 着色层 | 伙伴本体带主色调 | `partnerImg()` + CSS |
  | E. 认领页用回 SVG | 预览页用 `creature()` 的 SVG（消费 `c` 渐变） | 颜色直接进伙伴身体 | `renderSwatches()` 调用点 |
  1. 方案 C 实现：`renderSwatches()` 的 `onclick` 加 `pvEmoji.parentElement.style.setProperty('--aura',c)`，CSS `.aura{background:radial-gradient(circle,var(--aura,#fff3e0) 0%,transparent 70%)}`
  2. 选中后色板自身加 `.sel` 类（已有）+ 描边变 `--c` 色
  3. 颜色仍照常提交后端（`claim` body 带 `color`）
- **交互**：光环颜色用 `transition: background 0.3s` 平滑过渡
- **无障碍**：色板有 `aria-label="主色：{色名}"`；选中态有 `aria-pressed="true"`
- **验收**：选色板时伙伴下方光环颜色立刻变化；不同色肉眼可辨

## 二、P1 — 试用期增强（次优先）

### R67 大屏出题 + 口头答题 + 老师喂养模式

- **需求来源**：PRD R07——零学生设备的课堂答题
- **设计目标**：大屏出题 → 老师点选答对学生 → 伙伴即时反馈
- **设计要点**：
  1. 大屏新增「📣 课堂答题」模式入口（与现有学生端答题并存，老师可选模式）
  2. 老师选题 → 大屏全屏展示题目（3 米可读，字号 `clamp(2rem,5vw,4rem)`）
  3. 老师点选答对的学生（花名册浮层 / 直接点伙伴头像）→ 伙伴 `bloom` + 喂养粒子
  4. 错答不惩罚，仅不加分（无视觉反馈，避免羞辱）
  5. 模式切换：学生端答题（R47）/ 大屏口头答题（R67），老师课上随时切
- **交互**：大屏出题用 `requestFullscreen()`；退出 Esc；答对反馈 3 秒内
- **无障碍**：大屏字号符合 3 米可读；答对学生有文字 + 动画双重反馈
- **验收**：大屏出题 3 米可读；点选答对学生 3 秒反馈；错答无羞辱

### R68 随机点名抽选

- **需求来源**：PRD R13
- **设计目标**：一键公平抽选，动画可复现
- **设计要点**：
  1. 大屏顶栏新增「🎲 随机点名」按钮
  2. 点击后花名册以转盘动画滚动（CSS `@keyframes` 减速曲线）
  3. 可复现种子：`hash(日期 + 班级码)` → 当天多次点名结果一致（避免老师「重抽到满意的」）
  4. 结果展示：被选中学生头像放大 + 伙伴 `hop` + 「今天轮到 {名} 分享」文案
  5. 可设置「排除已点过的」开关（保证一节课内不重复）
- **交互**：转盘动画 2 秒减速；结果定格 3 秒后可关闭
- **无障碍**：按钮 `aria-label="随机点名"`；结果用 `role="status"` 播报
- **验收**：动画公平可复现；可排除已点；结果清晰

### R69 班级投票选伙伴线

- **需求来源**：PRD R14
- **设计目标**：全班投票决定本学期新伙伴形态
- **设计要点**：
  1. 老师端发起投票：选 3-5 个候选形态（从图鉴池选）→ 设定截止时间
  2. 学生端出现「🗳️ 班级投票」入口（课间可用）
  3. 投票卡片：候选形态预览 + 票数实时更新（15s 轮询）
  4. 截止后：得票最高形态解锁 → 全班伙伴墙统一庆贺动画（`evolve` 粒子大爆发）
  5. 每人一票（`device_token` 限制）
- **交互**：投票后卡片 `opacity` 渐变 + 「已投」标记；截止前可改票
- **无障碍**：投票卡片有 `aria-label`；票数用 `aria-live="polite"` 播报更新
- **验收**：老师发起 → 学生投票 → 截止解锁 → 庆贺动画

## 四、设计执行检查清单（每个任务开工前过一遍）

- [ ] 移动优先：先在 320px 验证再向上增强
- [ ] 断点行为明确：576 / 768 / 992 / 1200 各断点布局不塌
- [ ] 视觉层级：标题 / 正文 / 辅助文字三级清晰

- [ ] 动效：仅 `transform` + `opacity`，0.2-0.3s
- [ ] 状态完备：悬停 / 按下 / 加载 / 成功 / 错误 / 空态
- [ ] 设计 token：用 `p-4` 非 `p-[17px]`，用语义色非任意色值
